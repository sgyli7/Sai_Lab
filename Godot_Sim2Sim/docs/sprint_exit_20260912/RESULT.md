## 最关键的结论

1. 当前 CPU 负载的主要来源是 Jolt 采样和原生回放。两组 PPO 的神经网络更新均运行在 NVIDIA GB10/CUDA，但合计 893.31 秒采样、7.42 秒更新；这两个阶段中 **99.18% 时间在采样**。不能把这条流水线概括为已经充分使用 GPU。
2. 全 GPU 物理可以正常执行；目前问题是训练代理与游戏动力学、命令分布不一致。短时 CUDA 对照中补齐 Jolt 的转子惯量映射明显降低误差，但接触与状态投影仍存在偏差。没有证据把问题归为 GPU 张量训练本身有缺陷。
3. 增加 actor 速度/高度输入没有在本轮固定预算消融中胜出。模型结构扩展不是已经证实的改进方向；继续追加同类 CPU 采样 PPO 暂停，先校准 GPU 训练域。

## 网上高速经验与本地移植

[固定来源、代码审计和完整研究](../research_microduck_racing_20260912.md) 已找到公开可下载的 running 策略。作者报告身体前向约 1.65 m/s，但沿初始航向约 1.24 m/s、平均绝对 heading 31.3°；其 10 秒、70° tilt 生存判据不等价于本项目的直行、转向、停止要求，也未核实实机高速。

原始 ONNX 在冻结 Jolt 中进行 8 条起步/停止回放全部跌倒，进入 running 后约 0.78–0.98 秒首次跌倒。冷启动 4 条、先让源 actor 静置的 4 条也全部失败。350 行真实观测的原生/Python 最大 action 误差 5.33e-15，观测误差 4.80e-14；数值契约错误和一次性模型切换不足以解释全部失败。

离线同状态电机对照发现低速近似较接近，但高速饱和区不同。在固定 7.5 V、kp 200 的电气加粘性公式对照中，donor 与 Jolt 的扭矩差 RMS 为 0.1190 N·m，S05 为 0.00350 N·m；donor 31.52% 关节样本的源扭矩超出当前 Jolt 同状态可达范围。这是反事实公式对照，未包括干摩擦约束、延迟、供电历史和接触；不能将其写成实测净关节扭矩或已经确定的跌倒主因。

## 实际 CUDA 物理对照

使用 NVIDIA GB10、MuJoCo 3.10.0、Torch 2.9.1+cu129/CUDA 12.9，在 GPU 上运行 90 个首次跌倒前快照的 4×5 ms 物理步，保持各快照记录的关节目标。没有奖励优化，没有修改游戏。117 个初始投影快照中排除首次跌倒后的 27 个，不能把全 117 个投影统计混入这 90 个的评测。

| 20 ms 后对 Jolt 的误差，RMS | 匹配电机公式、保留关节 armature | 另外匹配 Jolt 转子对角惯量映射 |
|---|---:|---:|
| 身体位置分量 | 0.519 mm | 0.329 mm |
| 身体 COM 速度分量 | 0.0370 m/s | 0.0226 m/s |
| 身体旋转角 | 1.136° | 0.488° |
| 关节位置 | 0.01539 rad | 0.00646 rad |
| 关节速度 | 0.8234 rad/s | 0.3430 rad/s |

仅 S05 的关节速度 RMS 也由 0.4822 降至 0.2278 rad/s；所以改善不是单纯由 donor 的大幅动作贡献。该映射的某些对角惯量不满足实体三角不等式，是记录在案的研究近似；不能宣称已获得真实实体等价模型。

自由基座速度通过 COM Jacobian 重建，误差 <1e-8；但 Jolt 独立刚体的约束偏差无法全部投影到 MuJoCo 的关节坐标。相同 90 个快照中，左/右脚初始位置差 P95 为 2.22/2.14 mm，COM 速度差 P95 为 0.112/0.093 m/s，见 [投影记录](GPU_PROJECTION.json)。因此输出误差混合了初始投影和动力学差异，下一轮必须进一步拆分。

同 MuJoCo 模型的 4 个 CPU/GPU 短时检查中，初始样本 qvel 最大误差约 1e-7，另一些有接触的样本达 0.432 rad/s。没有假定 CPU 与 Warp 接触求解逐位相同；该检查不能作为纯算术错误定位。20 ms 对照也不证明长时稳定、训练吞吐量或策略迁移已合格。

## 接下来优先做什么

先让 GPU 训练域服从冻结游戏，再投入大规模学习：

1. 审计 GPU 任务构造后的质量、几何、碰撞过滤、HOME、关节和惯量，逐项对照实际游戏 spec。当前训练任务从 walking robot 构造，本次短时诊断从 scene_ball 来源构造，不能默认是相同接触资产。
2. 将状态投影误差与接触响应分开，分别覆盖离地、单脚、双脚、快速换向；在训练域适配电机、转子和接触代理。使用独立开发轨迹验证一决策步及较长开环片段，不改 Jolt 来追随训练结果。
3. 使用实际部署命令课程。现有 GPU 代理脚本 `lin_vel_y=(0,0)`，游戏路径纠偏却可请求 ±0.15 m/s；必须覆盖横移纠偏、idle→加速→A/D→退出→普通→停步，而非仅常量前向/角速度。
4. 上述误差明确且改善后，再比较 S05 与高速 donor 两个起点，GPU 并行采样和更新，Jolt 只做有界真实验证及必要的少量适配。普通段保留能力、高速段允许步态探索，不能用放宽方向/停止或降普通速度换分。

这是由本轮证据推导的方向；尚未完成 GPU 代理校准，也未证明它能在 Jolt 达到作者 1.65 m/s。
