# 下一轮训练方向：从短时残差修补转向任务、状态与运动结构

研究截至 **2026-09-11**。本地审计基于 `codex/overnight-20260911` 的 `a020052caa59c03603d9fca2a8505a8d00fd0b64`，并读取该轮留存日志。本文是下一轮的研究建议，尚未执行新的训练、物理修改或保留集评测。

> **后续决策（2026-09-11 晚）**：用户明确产品用于游戏开发，运行时坚持 Godot/Jolt。下文保留架构调查的比较依据，但“Godot＋原生 MuJoCo 物理”分支已排除，不进入实施计划。MuJoCo 只作离线对照／训练来源；下一轮在冻结 Jolt 中检验任务、状态与学习方法的改进。

## 结论与优先级

**当前需要改变训练问题的定义和适配方式，继续围绕九个旧策略逐项微调参数，预期收益有限。** 最先应解决的是命令与奖励冲突、actor 缺少任务状态，以及只能在旧策略附近修补的控制空间。现有实验不足以判定 PPO 不适合，也不足以证明增加训练时间就能达到原版 MuJoCo。

推荐顺序：

1. **把任务定义对齐实际操作，并建立原版 MuJoCo 的同任务参照。** 已发现轮滑转向命令与朝向奖励存在明确冲突；必须先修正，不能靠加样本抵消。
2. **在固定 Jolt 中训练能读取部署可用状态的策略。** 显式提供身体速度、接触、任务阶段等信息，比较小残差与允许充分更新的策略；先集中解决制动和行走。
3. **用同形态 MuJoCo 成功轨迹定义动作质量，并训练技能过渡。** 保留九个专家或分技能头，先解决进入、退出和恢复，再考虑统一网络。Disney BDX 的实际控制结构比通用人形大模型更接近本项目。
4. **把 Amazon FAR 的 FastSAC 作为有价值的算法对照。** 它的数据重用适合研究当前慢采样问题，但应在状态、任务一致后与 PPO 公平比较，不能照搬“15 分钟”的宣传口径。
5. **只有确认采样成本限制学习，才引入 GPU 训练代理和 ASAP 式动力学适配。** 更快地在另一个物理域训练，并不会自动修复 Jolt 接触差异。

另有一个产品架构分叉值得明确：**若长期目标主要是独立应用与原版动作质量，Jolt 并非必须，那么 Godot 渲染＋原生 MuJoCo 物理＋现有 ORT 是合理路线。** 用户给出的 Unity 项目实际就保留了 MuJoCo 物理。若 Jolt 是长期要求，则接受跨物理域学习的成本，最终在 Jolt 验证。这里是路线比较，不是改变本轮已冻结的物理要求。

| 判断 | 证据强度 | 尚不能推出什么 |
|---|---|---|
| 本地推理链已走通，主要质量缺口在控制与学习 | 高：独立包、数值与闭环证据 | 九技能已达到原版质量 |
| 轮滑部分转向课程的朝向目标冲突 | 高：源码与离线算例一致 | 它解释所有制动或行走失败 |

## 1. 当前究竟证明了什么

### 1.1 部署成功与动作质量要分开

现有 Linux ARM64 应用已内置 C++ GDExtension 和 ONNX Runtime 1.29.0，运行无需 Python/TCP；固定 Jolt 200 Hz、决策 50 Hz。最终包在禁网干净容器完成数值与回放检查，图形实时长测覆盖九技能与模型释放重载，30/144 FPS 的指定回放轨迹一致。因此，**下一轮不应再把“换推理框架”作为动作质量改善方案。** 完整证据见[上一轮结果](overnight_20260911/RESULT.md)。

| 现有最终结果：旧 Godot → 冻结候选 | 含义 |
|---|---|
| 站立、坐起、捡地、左右踢、轮滑蹲起：各 30/30 → 30/30 | 这些固定场景成功；不等于动作风格和任意切换都与原版相同 |
| 前滚：29/30 → 29/30 | 仍有同一质量缺口 |
| 行走七组：78/210 → 93/210 | 模型未换，收益来自单独记录的松键朝向控制 |
| 主动制动：0/210 → 180/210；候选零跌倒 | 明显改善，但 30 条超时，其中 4 条也持续倒滑，未过硬门槛 |

行走长直行仍是 5/30，左右转向和反复起停仍是 0/30；任务失败不全等于跌倒。轮滑原始 W3→S 已达 30/30，短推进 W1→S 仅 11/30。前者说明已有可行控制，后者说明**进入制动时的状态与近零速保持**比单一标称回放更关键。

轮滑最终收益主要来自状态反馈控制器及其回放参数搜索，不能记成 PPO 学习成果。下一轮应把这个冻结控制器作为强对照；新学习器若只能胜过旧的失败模型、仍不如已有反馈候选，没有替换价值。反馈候选可提供部分成功行为，但其已知失败区不能作为正确 teacher。

这些数字比较的是**旧 Godot 与新 Godot**。仓库有部分 MuJoCo/Godot 对照，但没有覆盖本轮完整操作协议的原版 MuJoCo 九技能同任务结果。因此现在无法负责任地回答“已经达到原版的百分之多少”，也不能把原版可能同样不会的主动制动全部算作迁移损失。

### 1.2 下一轮必须补齐三组参照

对同一组物理可比初态、命令语义和评分规则，分别运行：

- A：原版策略＋锁定版本的原版 MuJoCo 配置。
- B：同一原版策略＋当前冻结 Jolt。
- C：候选控制／策略＋当前冻结 Jolt。

**A−B 定位迁移损失，C−B 衡量目标域改善。** 若 A 也失败，应归入新增任务能力或操作定义问题。若 A 明显成功、B 失败，才有依据决定投入动力学对照还是策略适配。来源模型 SHA、关节顺序、命令、采样顺序、动作缩放和评分器必须留档；不得只让三个窗口“看起来做同一个动作”。

## 2. 本地训练瓶颈：已确认事实与待验证假设

本节的统计与合成算例保存于[训练审计 JSON](research_20260911_training_audit.json)。算例只调用现有定义做离线计算，没有运行新物理回合或使用保留集调参。

### 2.1 已确认：轮滑转向指令与奖励朝向相冲突

当前原生命令课程通过 [`schedules.py`](../src/sim2sim/research/schedules.py) 生成键盘回放；[`world.py`](../src/sim2sim/research/world.py) 优先使用该命令带。`roller_turn_brake` 中，按住转向时策略收到相对朝向命令，但奖励仍使用复位时设置的 `roller_target_yaw`。该条件没有随转向更新奖励目标，见 [`roller_tasks.py`](../src/sim2sim/research/roller_tasks.py) 和 [`rewards.py`](../src/sim2sim/research/rewards.py)。

在回放 4 秒处，命令前三维约为 `[0.6, 0, 1.0]`。固定其他合成状态，仅把相对初始朝向改为 0、0.5、1.0 rad，朝向奖励项依次为 **3.0、1.104、0.055**。也就是策略被要求转弯，奖励却持续偏爱初始朝向。

这是一项**可定位的目标定义错误**，不是“学习率还没找到”。它影响使用该课程和奖励的训练，不证明冻结反馈候选的所有失败由它造成，也不应误报为 walking 的第三维命令错误：walking 的对应量是偏航角速度，轮滑使用的是另一套相对朝向契约。

下一步应把轮滑操作明确为推进、转向、滑行、制动、停稳保持；转向期间如何更新目标，松转向／按制动时保持哪个朝向，需由同一任务状态提供给训练与运行。离线方向检查通过后才能启动学习。

### 2.2 已确认：奖励更偏好低速，没有完整表达“及时停稳并保持”

默认轮滑制动奖励的速度部分为 `exp(-speed²/0.09)`。在 0.1 m/s，即停稳阈值两倍速度时，仍可得到该项最大值的 **89.5%**；0.05 m/s 时是 97.3%。其他姿态和平滑项参与权衡后，缓慢滑行可能已经是一种容易维持的高回报行为。

现有奖励后来支持更窄的速度核和线性速度惩罚，且已做过相关实验。因此建议不是“再换一个 variance”，而是让策略学习**完整任务状态**：从什么时候开始刹车、近零速度是否持续满足、何时进入保持阶段、反向运动是否持续。评分器 [`standalone/score.py`](../src/sim2sim/standalone/score.py) 要求 0.2 秒滑动均速低于 0.05 m/s 并持续 1 秒，确认时间不超过 2 秒，另有姿态、距离和倒滑门槛；训练目标目前没有同样完整的持续时间成功事件。

建议用接近成功的连续进度信号帮助学习，同时保留独立硬判据；成功后仍运行保持阶段，不能以提前结束避开倒滑。计时、滤波和保持状态必须也是部署可用的状态。不要为了对齐指标把奖励仅改成一个极稀疏的成功开关。

### 2.3 已确认：基础 actor 缺少对制动直接有用的状态

[`obs.py`](../src/sim2sim/obs.py) 的基础 61 维观测为角速度、重力方向、关节位置／速度、上一动作和命令，没有机身线速度、接触和躯干高度；critic 的额外 26 维则含其中多项。

可以构造两份姿态、关节、角速度、上一动作和命令完全相同的状态，机身前向速度分别为 0 和 0.6 m/s，基础 actor 看到的输入仍相同。它无法直接区分此刻应保持还是继续制动。critic 多看信息不会自动改变 actor 的这个限制；历史可能缓解，但当前单步输入没有该历史。

**后期轮滑已经补过速度与高度，不能忽略这部分工作。** [`policy_state.py`](../src/sim2sim/policy_state.py) 用明确元数据声明 obs[58:61] 的新增状态，并屏蔽旧锚点对应输入；后期学习候选并未因此全部成功。上一轮固定反馈控制器的开发消融中，去掉前向速度后从 41/56 降到 6/56，支持速度反馈有用，却不证明只加观测就足够。[本轮消融记录](overnight_20260911/RESULT.md)

下一版应建立新的观测契约：基础本体状态＋身体坐标系速度＋经过验证的接触状态＋任务相关高度／方向＋阶段和计时。不要为了维持“61 维”继续把不同技能状态隐式塞进空槽。扩展输入是可控的原生接口迁移，需要同步 Python、ONNX、C++、复位与回放；不改变现有已冻结包。

### 2.4 强假设：小残差的权限与短探索限制了新能力

本轮正式学习运行主要是冻结 ONNX 锚点，加 `128→128` 的小残差网络，输出经 `bound × tanh` 限制。部分轮滑实验只在负油门时启用残差和探索，无法调整此前的推进／转向状态分布。源模型若已进入不利制动姿态，再限制修补范围，学习难度会进一步增加。

实际配置中 walking 约 25 分钟只有 **575,888** 个新采样，残差 bound=0.1，初始标准差 0.025，`freeze_std=10000` 使该运行内探索尺度保持固定。其余七项首轮各 6 分钟约 **0.11–0.20M** 样本。轮滑较长运行约 **0.57–0.77M** 新样本，不能据此否定一种完整学习策略的上限。

但日志也排除了一些容易误判的原因：已完成正式运行的 KL 回滚拒绝数为 **0**，没有证据表明它们因不断触发 KL 保护、学习率塌缩而学不动。部分残差输出确实较小，可能来自权限、惩罚或学不到改善；仅看输出幅度不能作因果判断。

[`models.py`](../src/sim2sim/research/models.py) 已有允许完整网络增量的 `anchor` 路径，当前主要跑的是 `residual`。两者的正则也不同：[`train.py`](../src/sim2sim/research/train.py) 的 residual 主要惩罚目标域状态上的修正幅度，不应把所有运行统称为完成了正式 teacher/student 蒸馏。下一步要比较**有界修补与更自由的目标域优化**，并量化旧任务回退，而不是只扫描不同 bound。

### 2.5 采样成本是真问题，但尚未完成性能归因

现有训练使用 8 个 Godot 环境，Python 组织通信；锚点 ORT 使用 CPU 单线程并逐样本调用，actor/critic 更新也在当前 CPU 路径上。日志中不同运行的采样速率中位数约为 **322–595 个决策转移/秒**。这些数值含当时并发工作影响，不是隔离性能基准，更不能直接证明 TCP 占主要耗时。

以 400 转移/秒作算术示例，1M 样本约 42 分钟，10M 约 6.94 小时；还没加入多训练种子、导出和验收。不能把数千 GPU 环境论文的 15 分钟直接套在此处，也不能把“九项各有一个目录”当作九项都得到充分学习。

下一轮先分别测物理、场景回调、状态序列化／通信、锚点推理、rollout 整理和梯度更新耗时，再决定做批量推理、Godot 内 C++ 批接口还是 GPU 代理。原生应用推理已足够快，**部署推理延迟与训练采样吞吐是两个问题**。

### 2.6 动力学存在结构差异，贡献大小尚待测量

[`physics_server.gd`](../godot/physics_server.gd) 将关节空间 armature 近似到子刚体对角惯量，并设置惯量下限；执行器使用显式 PD、饱和、阻尼及 `tanh` 摩擦。MuJoCo 与 Jolt 的接触、摩擦表示也不能通过复制一个数值变成等价。这些是已知近似，尚不是本次已证明的首要失败原因。[MuJoCo 接触文档](https://mujoco.readthedocs.io/en/stable/computation/index.html#contact)、[Jolt 架构](https://github.com/jrouwe/JoltPhysics/blob/master/Docs/Architecture.md#friction-and-restitution)

应在固定目标 Jolt 下依次做单关节响应、全身悬空运动、轮地无控制滑行、有限制动动作响应，分离执行器与接触贡献；同时判断被动轮在当前动作权限下的制动可控性。现阶段没有证据说该任务物理上不可能，也不能保证任何姿态都能在两秒内恢复。

Godot 文档特别说明 Jolt 的接触冲量接口是预估值，多接触情形精度有限；当前审计没有发现奖励使用数值冲量，因此这是**未来接触标签的校验要求，不是已经确认的现有奖励 bug**。[Godot 官方说明](https://docs.godotengine.org/en/stable/tutorials/physics/using_jolt_physics.html#contact-impulses)

## 3. 最新论文与工业落地：哪些经验能迁移

### 3.1 先区分三种证据

“公司参与的论文”“机器人真机演示”“客户持续运行”是不同证据。近期材料不足以证明某个通用网络已能直接解决 MicroDuck 九技能；很多量产系统没有公开足够细节，无法反推出完整训练配方。

| 来源 | 已核验的部署证据 | 对本项目的意义与边界 |
|---|---|---|
| ANYbotics Trekker，2023 | 官方称 RL 控制经真机测试后更新到巡检机群 | RL 确有商业运行依据；没有公开完整产品策略、训练成本与失效率。[官方说明](https://www.anybotics.com/news/superior-robot-mobility-where-ai-meets-the-real-world/) |
| Agility Digit，2024–2025 | GXO 客户确认多年度仓库部署；Agility 另确认板载 RL | 客户与技术两侧证据成立，但不能把某一论文算法精确对应到该仓库全部动作。[GXO](https://investors.gxo.com/news-releases/news-release-details/gxo-signs-industry-first-multi-year-agreement-agility-robotics/)、[Agility](https://www.agilityrobotics.com/content/agility-robotics-expands-relationship-with-nvidia) |
| Disney BDX，RSS 2024／2025 实景运营 | 论文自报约十小时公开操演无跌倒；官方确认乐园与邮轮使用 | 形态和用户操演方式最接近；人工操演与长期自主可靠性仍有区别。[^bdx] |
| Amazon FAR FastSAC，2025-12 | G1/T1 真机行走、公开训练代码 | 可复现算法路线，属于研究真机证据，未证明 Amazon 仓库已量产采用。[^fastsac] |
| Boston Dynamics Atlas，2025–2026 | 运动参考＋RL 真机展示，2026 产品制造／部署声明 | 支持参考运动方向；出货安排不能代替公开的长期成功率。[动作说明](https://bostondynamics.com/video/walk-run-crawl-rl-fun/)、[产品进展](https://bostondynamics.com/blog/atlas-evolution-from-research-robot-to-industrial-humanoid/) |

### 3.2 最接近的范式：Disney BDX 的参考运动＋专家＋相位过渡

BDX 是 **RSS 2024 工作，2025 年 arXiv 补录**，不应包装成新发表的 2025 算法。它同样是 14 个受控自由度的小型双足角色，使用多个运动专家、参考动作和相位信息。行走退出等待双支撑，转弯起步考虑迈腿相位。论文消融中，仅速度奖励会产生碎步；加入接触相位仍不如参考运动自然。最终每策略约两天 RTX 4090，半小时仅为名义动作预览。[^bdx]

**对 MicroDuck 的建议：**

- 用原版 MuJoCo 成功动作作为同形态参考，减少凭空设计“踢得好、滚得自然”的奖励。
- 区分连续技能与一次性技能：行走／轮滑用命令和阶段驱动；坐起／踢球／前滚用参考进度、任务完成与恢复驱动。
- 训练实际切换入口，例如滑行或蹲起结束后进入制动，不只从标准 home pose 起步。
- 先保留九专家，增加明确的进入、退出和恢复条件；不对两个冲突技能的动作直接平均。

这不是照搬 BDX 机器参数。它支持的是控制结构选择；MicroDuck 的被动轮与接触仍需自身验证。

### 3.3 最新且值得比较的算法：FastSAC，而不是先把 PPO 判死刑

Amazon FAR 于 2025-12 发布的工作用 FastSAC/FastTD3 展示 G1/T1 全关节行走，单 RTX 4090、数千并行环境约 15 分钟；舞蹈跟踪另用 4×L40s、16,384 环境，不能混称都只需 15 分钟。作者公开 Holosoma，配方不仅换优化器，还包括动作范围、归一化、价值分布建模和探索。[^fastsac]

其与本项目最相关的理由是：**慢仿真情况下，off-policy 方法能重复利用已采样转移，减少每次更新都必须新采样的成本。** 这值得与当前 PPO 做对照，但有三个前提：

1. 观测能辨识任务状态，奖励与命令一致；反复学习错误目标只会更快得到错误答案。
2. replay 记录完整原始状态、阶段、终止原因和版本。旧控制、旧物理或不可重算奖励的数据，不能无条件混入。
3. 同时比较等新样本量与等实际时间；允许两算法使用预先限定的合理配置范围，并把调参成本算入。

PPO 仍出现在 PACE、BeyondMimic 等近期真机工作中。NVIDIA/Boston Dynamics 的 Spot 工具包也公开了普通 MLP/PPO 到 ONNX 的实机路径；这不是量产 Spot 默认策略，但足以说明“当前短时 PPO 没晋升”不等于 PPO 方向过时。[^pace] [Spot 官方训练与部署说明](https://developer.nvidia.com/blog/closing-the-sim-to-real-gap-training-spot-quadruped-locomotion-with-nvidia-isaac-lab/)

### 3.4 PACE：用分级响应辨识替代盲目域随机化

PACE 首稿 2025-09，2026-07-31 v2／IJRR 2026。它依次验证单执行器、全机悬空运动、地面行为，拟合惯量、阻尼、摩擦、偏置及延迟；三主平台和十个追加机器人提供实机证据。约 20 秒数据并不意味着低计算成本：文中辨识使用 4096 环境，单 GPU 约 10–24 小时。它不依赖广泛执行器动力学随机化，但仍包含地形、摩擦和扰动变化。[^pace]

对本项目最有用的是**辨识顺序**。固定 Jolt 为目标，测出源域哪里不匹配；若需要快速代理，调整训练侧模型来逼近目标。不要一边改目标物理、一边改奖励、一边调策略，最后无法判断改善来源。PACE 的 Isaac Lab 代码不能直接作为 Jolt 插件，也没有必要完整复制其计算规模。

### 3.5 ASAP：把 residual 放到训练模拟器里，含义与当前不同

ASAP（2025）先收集目标域轨迹，在源模拟器内学习动作等效的动力学修正，再冻结该修正来优化控制策略；**最终部署不带这个动力学修正模型**。论文包含跨模拟器与 G1 真机实验，源码已公开。[^asap]

当前方案是部署时 `旧策略＋策略残差`；ASAP 是训练时 `快速源物理＋动力学修正`。两者不能只因都叫 residual 就认为已经尝试过同一方向。

对固定 Jolt、慢采样的 MicroDuck，可研究 MuJoCo/MJWarp 提供快速训练，训练侧修正逼近 Jolt。但只有源域足够快、目标轨迹覆盖相关状态、误差可由动作等效表示时才值得做。接触拓扑或摩擦表示差异未必能由小动作修正充分表达。

2026-04 的本体分布匹配论文给出重要反例：Digit 倒退持续跌倒、缺乏有效轨迹时，研究者未能辨识对应差异，后续微调仍重复失败；作者进一步指出，低匹配成本可能对应不具有物理意义的倒地分布。它的少量真机数据之前还有约 19.66 亿预训练样本。因此代理必须通过留出短轨迹和闭环任务验证，不能只看辨识损失。[^distribution]

### 3.6 BeyondMimic、RMA/HIM、MUJICA：取机制，不整套照搬

**BeyondMimic（2025，已核对 11 月 v4）：**借鉴参考跟踪与困难动作段自适应采样。先从原版成功轨迹取得根部方向、关节、足／轮接触和恢复阶段；对 Jolt 保留跟踪容差，允许为稳定偏离逐帧动作。v4 的 guided diffusion 在板载 Mini PC／RTX 4060 Mobile 上运行，相关控制为 25 Hz，与本项目 50 Hz ARM CPU 条件不同；它不是采用参考跟踪训练的必要部署组件。[^beyond]

**RMA/HIM（2021／2024）：**历史适配和速度估计针对真机不可直接测得的状态。MicroDuck 最终在引擎内运行，真实速度等状态可直接读取，先做可部署全状态策略更直接。将来上实体机器人再考虑历史 student，不要现在主动制造观测瓶颈。[^state]

**MUJICA（2026）：**显式技能上下文、时序状态估计、低层能力先于高层调度有参考价值；其 Go2-W 是四足主动轮，本项目是双足被动轮，轮扭矩动作不能移植。按钮已经提供技能选择，当前没有必要先学一个自动高层选择器。[^mujica]

SONIC（2025→2026）与 HoloMotion（2026）的公开成果值得跟踪，但分别涉及大规模动作数据和大模型。SONIC 最大实验约 21k GPU 小时；HoloMotion 报告 0.4B 参数与 2000+ 小时动作。这些不是当前有限预算下最先该承担的工程与数据成本，也没有证据表明可以直接适配 MicroDuck。[^large]

## 4. 物理与训练架构的分叉

### 4.1 “独立运行”不等于“必须换成 Jolt 物理”

用户给出的 Unity 项目保留原生 MuJoCo 3.12 作为物理权威，Barracuda 负责推理。其效果不能用来证明 PhysX 或 Jolt 已达到 MuJoCo 等价。固定版本源码中的 `MujocoPolicyStepper` 可核验这一点。[^unity]

| 路线 | 何时合理 | 主要代价 |
|---|---|---|
| **Godot＋原生 MuJoCo＋ORT** | 产品优先原版动作质量，且可以让相关世界物理由 MuJoCo 负责 | MJCF/资产装载、渲染同步、交互世界表示、生命周期与打包 |
| **Godot/Jolt＋目标域直接训练** | Jolt 交互是长期要求，采样量可接受 | 策略需要真正适应目标接触与执行器表现 |
| **快速 MuJoCo/MJWarp 训练＋Jolt 适配** | Jolt 必须保留，但直接训练太慢 | 额外辨识、域差距、双栈维护和迁移验证 |

第一条仍能实现无 Python/TCP 的独立应用；地面、球和所有影响机器人的碰撞应由同一个物理系统处理。不能简单让 MuJoCo 管机器人、Jolt 管球，再认为双向受力自然一致。它有机会移除主要跨域差异，**不保证原版本来不会的刹车和新交互任务自动解决**。

在用户改变长期物理取舍之前，执行主线仍按冻结 Jolt 设计。本文没有切换引擎，也不建议用新引擎结果冒充通过旧 Jolt 验收。

### 4.2 加速框架优先考虑适配成本，不按发布新旧排序

当前已核版本中，MuJoCo/MJWarp 3.13.0 于 2026-09-09 发布；mjlab 1.6.0 于 08-09 发布但依赖锁定 `~=3.11.0`。因此“把最新版都装上”不是兼容方案。旧 MuJoCo 3.12 参照应继续锁定，框架试验单独隔离。[^framework]

对于已有 PyTorch/ONNX 路线，**mjlab/MJWarp 是第一候选调查栈**；若能直接复用上游 Playground 的具体任务，MJX/Playground 也值得比较。Newton/Isaac Lab 多后端与复杂交互有价值，但目前单机器人平地九技能没有必要先引入完整 Isaac Sim。Isaac Lab 3.0 已有 kit-less Newton 路径，但仍需按 beta 发布锁依赖，不能与任意最新 solver 混装。

Warp 和 JAX 的官方支持提供 Linux aarch64 底层可行性，**尚没有本次在 GB10 上跑通 MicroDuck 全套新训练栈的实测**。若进入此分支，先做模型加载、物理特性核对和 16/64/256/1024 环境吞吐曲线，分别记录编译、有效决策转移、内存和接触容量溢出。不用 4090 或数据中心 GPU 的成绩预测 GB10 收益。完整版本、许可与 ARM 边界见[架构调查附录](research_20260911_simulator_architecture.md)。

## 5. 下一轮应按什么顺序做：可证伪的实验计划

### 5.1 第一道门：先交付诊断包，不先启动九技能训练

诊断包包含：

1. **任务契约表**：每技能的坐标系、命令单位、时间／相位、保持目标、上一动作、切换和复位规则；明确 roller 与 walking 第三维语义不同。
2. **奖励方向检查**：要求转向却奖励不转、要求保持却奖励继续移动等合成反例；修正后的逻辑需能解释每个奖励项在任务各阶段的作用。
3. **A/B/C 三组任务参照**：新开发数据上的 MuJoCo、原策略 Jolt、当前候选 Jolt；先覆盖基础／转向行走，W1/W3 制动和转向后制动。
4. **失效前窗口**：进入制动时的前／侧向速度、倾角、角速度、高度、接触和关节状态；保留完整前缀与近停阶段，避免把倒地后的状态当原因。
5. **分级动力学响应和训练耗时剖析**：冻结物理，记录哪些偏差能由控制弥补、哪些尚不确定，以及每百万样本的实际成本。

未通过命令和奖励检查时，不继续训练；尚无 MuJoCo 同任务参照时，不宣称“迁移差距已定位”。这些检查不是一次性全部修好九技能，而是为接下来的路线实验提供可信前提。

### 5.2 最小路线实验矩阵

先用**一个制动任务族＋一个行走任务族**做判别，再扩展九技能。每一行只检验一个主要假设，依赖前一行已固定的契约；不把全部新模块一次性堆进候选后与旧版比较。已有冻结反馈候选作为所有制动学习实验的共同对照，在新开发场景上测量；不重跑旧 holdout 来挑选路线。

| 编号／假设 | 比较组与固定项 | 什么结果支持继续 | 什么结果应停止该方向 |
|---|---|---|---|
| R0：任务冲突妨碍学习 | 先做离线语义检查；再比较旧／修正目标，输入、控制权限与预算一致 | 转向目标不再自相矛盾；独立任务指标与奖励趋势一致 | 语义未修复就停止训练；只涨奖励不算成功 |
| R1：actor 状态不足 | 旧观测 vs 显式状态；同一已修正任务、PPO、动作空间与课程 | 多训练种子中停稳／方向改善，巡航与姿态不退化 | 两组都不学会时，先查目标与控制权限；不立即堆 RNN |
| R2：哪种适配路线更有效 | 同一状态、任务与预算，有界残差 vs 旧策略初始化后充分更新；先完成状态兼容 | 更自由路线解决原有失败且满足旧任务门槛；先只得出路线优劣 | 若要归因于动作权限，另做同参数化／正则的权限消融；全量更新破坏旧能力不晋升 |
| R3：数据重用改善效率 | 同一可部署状态／任务，PPO vs FastSAC；预先限定各自配置预算 | 等新样本和等时间两种视角下，成功／质量有稳定收益 | replay 估值好但未见场景差，不扩充调参；算力开销抵消采样收益则保留 PPO |
| R4：参考与过渡改善质量 | 一个完整技能：任务目标 vs 加同形态参考；再独立比较难段／入口课程 | 方向、平顺或恢复改善，完整前缀成功不回退 | 只会理想片段、完整进入仍失败，停止扩展；缺少成功示范的任务不用模仿替代学习 |
| R5：快速源域值得维护 | 直接 Jolt 学习 vs 快速源域预训练＋目标域适配，分别记两域样本 | 全部准备／辨识时间计入后仍有收益，留出 Jolt 闭环无退化 | 单步拟合好但长程接触或任务更差，停止代理扩张 |

R1 的价值不能用“之前已经加过三维”直接判死：之前同时受小残差、课程和目标限制；但也不能省略已有负结果，重新宣称第一次发现速度。R1 可采用相同扩展网络，一组屏蔽新增状态，另一组提供真实值，避免同时改网络容量。

R2 是适配路线比较，不能直接作为“残差幅度造成失败”的因果证明：现有 `residual` 与 `anchor` 同时改变参数化、网络容量、计算精度和正则数据。若需要定位权限贡献，另做同参数化、同初始化、同正则，仅改变允许修正范围的消融。仓库虽有完整网络增量路径，`Policy` 目前明确拒绝 `state_input + anchor`；**新状态契约兼容与导出对照是 R2 的实现前置**，不能直接把两种模式切换运行。仅有 ONNX 时验证权重恢复或用成功行为克隆初始化，不假定训练检查点齐全。

每个学习比较先做小规模数值／学习曲线筛查，再用至少 **3 个独立训练种子**复核；环境初态种子和训练随机种子是两回事。可先以每配置 0.25M 新转移检查 NaN、目标方向和明显停滞，再把有进展的比较扩至 1M 及以上。**这些是拟议筛查预算，不是“1M 不成功即算法无效”的规则。** 到上限仍有学习趋势而样本不足，应记为未定，按剖析结果决定追加，不用一次短跑下结论。

若仍约 400 转移/秒，单个 1M 配置约需 42 分钟，两个配置×三个训练种子仅采样已约 4.2 小时。因此不应承诺在下一次八小时内完整跑完所有分支；应先完成诊断，选择信息价值最高的一组对照。最终测试和交付时间仍需单独保留。

### 5.3 任务与数据应如何组织

**轮滑**：完整任务链为静置→推进→可选转向／滑行→制动→保持→再次启动。训练变化首先来自命令时序、初态和前一技能终态；保持已冻结质量、重力、碰撞和执行器。近停难例可提高采样概率，但必须混入完整起步前缀与可实际到达的中间状态，不能仅传送到漂亮的制动姿态。

**行走**：分别学习移动期间速度与方向、减速／停步、停后保持；先测真实命令响应，再加入速度相关参考与相位。避免通过短碎步或普遍减速提高姿态分，配对平均速度继续满足旧版至少 95% 的原约束。

**其余七项**：从 MuJoCo 成功回放建立参考与恢复阶段，先挑一个已有明确失败边界的完整技能验证方法，再扩展。对于已经 30/30 的固定场景，比较朝向、冲击／动作变化、恢复时间与连续操作，而不是用奖励涨幅声称成功率提高。前滚参考跟踪仓库已有局部支持，应复用并审计其覆盖，不能把参考学习当成完全空白。

**多技能结构**：保留技能 ID 和明确状态机，学习器处理身体控制。连续技能到一次性动作、动作恢复到站立、步行机器人到轮滑机器人的切换分别记录；换机器人属于资源／状态重建，不能靠策略隐式猜测。共享骨干或蒸馏仅在单项能力和过渡都可靠后比较，避免九技能同时出现负迁移。

### 5.4 验收、数据隔离与停止条件

- 旧 `916000–916029` 已使用，下一轮只能作为历史回归，不能重新冒充未见保留集。新增训练、开发、系统辨识验证和最终测试四种用途要分开，记录生成规则与数据 SHA。
- 当前 23 条回放主要是固定命令带加初始 yaw／关节扰动。下一轮开发集应覆盖推进时长、转向持续时间、命令幅度、操作顺序和进入状态；增加初态种子数量不等于覆盖这些任务变化。
- 物理／控制契约、观测、奖励、数据课程、算法分别版本化。控制修复与模型改变建立独立对照；跨契约旧 replay 只有字段足够且转换／重算可靠时才复用。
- 先看无跌倒、任务成功和无旧成功回退，再比较平顺、方向、恢复和速度。确认停稳时间、持续倒滑和距离沿用原门槛，不因新方法改变标准。
- 原生接口一旦更新，重新做 Python／原生数值与控制序列对照，保留 `1e-5` 门槛、200/50 Hz 和独立导出验证。训练框架不必进入最终包。
- 候选冻结后一次性做新最终评测；结果不反哺同轮参数选择。完整操作质量与含显式复位的生命周期演示继续分开。
- 每个分支预先写失败、停止和恢复条件。数值失败有明确的有限重试；无信息增益的重复搜索停止；预算不足以完成评估的候选不启动。

## 6. Auto-Research 应从“调参机器”改成“假设管理器”

Karpathy 的 autoresearch 固定数据准备与评测，让 agent 修改训练程序，用固定训练预算和单一验证指标保留／回滚实验；它本身不是机器人训练算法。其五分钟预算针对该语言模型实验，并排除部分启动开销，不能直接当作九种物理任务同等充分学习的依据。[^autoresearch]

本项目可以保留已有工时账本、超时、检查点、冻结与回放机制，但新调度器的实验单元应是一条**可被推翻的架构假设**：

| 每次必须记录 | 作用 |
|---|---|
| 假设、反例与预测；主要改动只有一项 | 分清“速度信息不足”“控制权限不足”“数据不足” |
| 源模型／数据／物理／控制／奖励／观测版本 | 保证失败可复现，避免跨契约混比较 |
| 两域各自的新样本量、replay 重用、实际工时、准备开销 | 区分算法样本效率与基础设施加速 |
| 多训练种子曲线、任务成功、失败类别、旧成功损失 | 防止偶然种子和奖励投机晋升 |
| 去留、尚未排除的解释、下一项判别 | 防止仅因为预算剩余而继续扫参数 |

调度顺序应支持先淘汰方向错误的短实验，再把预算集中到有学习趋势的路线；不能将一切失败都继续缩小学习率。需要预先限定各算法的合理调参预算，避免把调参能力误算为算法能力。

静态 Godot 环境与资源应按内容校验后共享，只保存候选差量和必须证据。上一轮曾因逐候选复制工程产生大量重复数据，去重回收约 584 GiB；这类成本会直接侵占有效研究时间，不能靠扩大搜索次数掩盖。[既有记录](overnight_20260911/RESULT.md)

## 7. 最终路线建议及仍未解决的问题

**建议将下一轮命名为“任务一致性与目标域控制学习”，首先完成诊断包，再做 R1/R2 中最能区分瓶颈的一组实验。** FastSAC 是紧随其后的算法挑战者；参考运动和相位过渡是提高动作质量的主线；GPU 代理和九技能统一网络是有条件的后续投入。

这与继续微调的区别在于，下一轮允许改变 actor 能看到什么、学习什么阶段、能偏离旧动作多远、如何使用原版参考，以及如何利用采样数据；每项改变都要有独立证据。旧模型只作为来源、对照或初始化，不再默认是目标域每个状态的正确 teacher。

目前不能承诺达到原版 MuJoCo 水准，原因不是原生推理还没完成，而是缺少完整同任务源域基准、目标域控制能力尚不均衡，以及 Jolt 接触差异贡献未量化。最短路线取决于产品物理选择：**保留 Jolt，就投入目标域状态、任务与适配；允许原生 MuJoCo，则优先验证能否直接消除主要域差距。** 两种路线都保留独立应用目标。

本次未启动训练、修改运行时代码／物理、替换模型或重跑旧保留集。这里的路线收益均为待验证建议；已确认的源码问题、历史结果和论文实测已分别标注。
