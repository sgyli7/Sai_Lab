# MD 的 Shift 与前向步态：实测纠偏

本次复现桌面“小小维修站”的实际准备资源与原生控制。**Shift 能触发，但现有成果只证明加速行走，尚未证明学出了用户期待的前向跑步。** 原先“400/400 达标”的表述没有交代这个任务定义缺口。后退确实比前进快，不是用户错觉。

## 同起点、同场景测量

| 输入 / 模型 | 命令 m/s | 实际根部位移速度 m/s | 单步长度估计 | 换脚频率估计 |
|---|---:|---:|---:|---:|
| W / S05 | +0.25 | +0.1885 | 4.74 cm | 4.17 次/s |
| 左 Shift+W / a402 | +0.30 | +0.2340 | 5.64 cm | 4.17 次/s |
| S / S05 | -0.30 | -0.2870 | 7.19 cm | 3.85 次/s |
| 普通 S05、等幅正向命令 | +0.30 | +0.2301 | 5.70 cm | 4.17 次/s |
| 普通 S05、等幅反向命令 | -0.25 | -0.2375 | 6.11 cm | 3.85 次/s |

表中速度用实际身体位置测量；步态来自单个确定性起点 1.5–4.4 秒窗口，不能当成大样本统计。Shift 比 W 快约 24%；后退比 W 快约 52%。即使比较同幅命令，反向跟踪也更快，所以后退现象不能只归因于默认命令不对称。

第二个独立 X11 检查通过操作本测试拥有的真实游戏窗口注入系统按键，测得 W / Shift+W / S 为 **0.1897 / 0.2364 / -0.2890 m/s**。模型选择分别是 walking / sprint / walking。没有复现“Shift 完全无效”；用户使用不同键盘或远程输入的差异仍不能由这一次系统注入排除。

保持 W、只按下和松开左 Shift 的引擎事件回放，三段实测为 **0.1987 → 0.2489 → 0.1904 m/s**；复位也通过。另一次连续 X11 测试在窗口失焦时按保护逻辑停止，未继续向其他窗口发按键；不计为通过。

## 身体与双腿实际在做什么

[步态曲线](gait_comparison.png)显示：当前加速主要增加了一点步长，换脚频率几乎不变。普通前进 / 加速 / 后退平均躯干俯仰约 **+2.12° / +3.35° / -3.74°**；正号朝机器人头部方向。后退的单步更长、双支撑占比约 4.8%，低于加速的约 12.4%。这些运动学差异与用户“后退更像跑”的观察一致，但还不能据此证明某个奖励项就是唯一原因。

全身重心由所有有质量机器人刚体的同帧惯性中心加权计算，排除球。读取这些额外状态后，三条原始回放的观测、动作、控制目标与上一动作均逐帧完全相同。支撑图使用的是接触脚的踝部中心，不是压力中心或完整支撑多边形。落脚前后速度变化只是运动学统计，不能当作已经测得地面水平冲量。接触按 60 ms 中值过滤；当前短窗口没有双脚同时无接触的帧，这也不能单独作为“是否跑步”的判据。

## 只提高命令行不行

只做了一个事先固定的反事实：`sprint_vmax_x` 从 0.30 改为 0.45，模型和其他控制不动。在桌面场景短直线上能到约 0.341 m/s，但侧向漂移变大。

用全套八种既有加速课程和新开发种子 929100–929103 配对：

| 配置 | 完整通过 | 跌倒 | 长直行速度 |
|---|---:|---:|---:|
| 原配置 0.30 | 32/32 | 0 | 约 0.232 m/s |
| 单纯提高到 0.45 | 10/32 | 0 | 约 0.332 m/s |

22 条新增失败涉及直行偏航、转向不足、退出加速后的控制质量。**拒绝采用。没有靠降低普通前进或后退速度制造相对改善；本轮没有替换模型、提高默认速度或改变 Jolt 物理。** 最终保留种子 929200–929229 未用。

## 对训练方向的修正

现有 a402 是 S05 周围的有界残差策略；训练保留慢走教师，主要优化命令跟踪、方向、停步、平衡与动作平滑。源码中没有明确的支撑 / 摆腿相位任务，且俯仰和侧倾共用一个超过约 6.9° 后增加的姿态代价。以上是代码事实；“它们把新步态限制在旧快走附近”仍需受控消融确认，不能直接宣称已证明因果。

下一轮应以**身体前送、落脚承接、支撑腿再推进**为任务，先争取原生 Jolt 中 0.35 m/s 的完整直行、转弯、起步和停步能力，再增加速度。新的方向为：

1. 用明确的步态相位描述左右支撑与摆动，记录重心、脚落点、脚滑移和关节做功。先补齐原生接触冲量的坐标与采样核验，避免把接触抖动当成腾空或蹬地。
2. 为前向动态步态建立足端 / 重心参考或周期接触任务。前倾随速度与步态阶段形成，不直接奖励“摔倒”，也不固定一个前倾角硬压身体。
3. 普通行走保留独立冻结策略；候选 sprint 在普通 / 停止过渡处保留教师约束，对持续加速段比较全量可学习 actor 与现有小残差，确认是否需要放开旧步态束缚。
4. 做受控比较：先固定学习容量比较“有 / 无相位任务”，再固定任务比较“有界残差 / 全量 actor”，每组同预算、同课程。GPU 采样 / 学习，少量原生 Jolt 验收；不重新开启已失败的无差别接触参数搜索。现有 GPU 代理与 Jolt 的接触差异仍是门槛，须在新步态的落地 / 推进段重新检查。
5. 加入与慢走等命令的对照以及独立步态验收。仍要求无跌倒、无偏航、可连续 A/D、可安全退出加速；仅速度多 15% 或训练奖励上涨，不能再代表跑步完成。

这些方向有实机研究依据，但尚未在 MicroDuck 上验证：[周期奖励组合的 Cassie 实机步态](https://arxiv.org/abs/2011.01387)用足端力和速度的周期任务区分步态；[简化刚体参考轨迹方法](https://arxiv.org/abs/2207.04163)在 Cassie 上实现了 grounded running，说明不应只以腾空判定动态步态；[2025 年 Cassie 综合控制研究](https://journals.sagepub.com/doi/10.1177/02783649241285161)为跑步及跑步转站立提供明确参考，并验证长距离实机运行。这些机器人的成绩不能直接视为 MicroDuck 可达到的速度。
