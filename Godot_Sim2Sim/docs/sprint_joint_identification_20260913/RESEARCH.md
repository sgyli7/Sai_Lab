# 关节残差与冲刺反向输入：2026-09-13

本轮先诊断 GPU 训练域与固定 Jolt 游戏域的差异，再检验一个明确的输入过渡假设。**没有更新策略权重，没有采用新的 GPU 物理代理，也没有修改游戏物理参数。** 最终产品验收独立记录在 [RESULT.md](RESULT.md)。会话目录为 `results/sprint_joint_identification_20260913/`，起点提交 `d357400b56df25d5f7a7482efeccafe9245d6249`。

此前 a402 策略已通过 CUDA 物理采样和 CUDA 学习训练。其 Jolt 开发结果为加速 127/128、普通行走 128/128、历史回归 7/7，零跌倒；仅 `sprint_alternate / 927001` 第二次转向响应不足。CPU 忙碌不等于优化器在 CPU 上学习：本轮 CPU 用于原生 Jolt 轨迹、离线几何分析和产品验收，MuJoCo/Warp 代理实验仍用 GPU。

## 连接几何确实不同，不能直接当成弹簧

采集 16 个开发种子的同帧刚体 COM 位姿，450 决策帧/回合。诊断开启、关闭及原始轨迹的观测、动作、上一动作、命令、控制目标全部逐帧完全一致。用资源中的惯性坐标变换、局部连接点、静止相对旋转和铰链轴分解连接误差：

- 独立恢复的铰链角与原生角度最大误差 `4.63e-7 rad`，低于 `1e-5`。
- 同时使用实测连接平移和相对旋转后，全身位置重建误差最大 `4.07e-16 m`。
- 理想连杆脚位置残差与此前独立 MuJoCo FK 结果的差异最大 `1.95e-8 m`。
- 落地、站立、前进、左右反向阶段，只保留连接平移即可消除至少 99.7% 的脚位置重建均方误差。只保留锁定轴旋转，改善约 2%。

这是**实测几何的表示能力**，并不证明这些误差是物理弹性，也不证明它们独自造成转向失败。不同关节和左右腿的残差不同，所以先用训练半区种子 927000–927007 的落地/站立窗口拟合每关节标量刚度；验证半区为 927008–927015。拟合误差降低，但真实短时代理响应并未通过。

| GPU 代理 | 验证区落地综合误差/刚性基线 | 站立 | 移动 | 采用 |
|---|---:|---:|---:|---|
| 按关节拟合平移弹簧 | 0.492 | 1.845 | 1.462 | 否 |
| 分离位置投影 | 2.653 | 15.387 | 17.111 | 否 |
| 硬速度投影＋位置投影 | 0.969 | 5.375 | 6.123 | 否 |

各组也有刚性基线、原有统一 20000 刚度对照，以及速度单独处理的消融；三组共 11 个完成的物理配置回放。完整门要求落地和移动综合误差各改善至少 20%，任何组成项、站立误差不得回退超过 10%，并通过预接触与脚几何检查。**没有配置通过，不启动依赖它们的 PPO 训练。**

## 为什么简单的 GPU 弹簧/投影没有解决差异

本机 Godot 是 `4.7.2.stable.official.ed1daf0bf`。对应版本的 [Jolt 依赖记录](https://github.com/godotengine/godot/blob/ed1daf0bf/thirdparty/README.md)及 [PointConstraintPart 源码](https://github.com/godotengine/godot/blob/ed1daf0bf/thirdparty/jolt_physics/Jolt/Physics/Constraints/ConstraintPart/PointConstraintPart.h)显示：速度约束与位置稳定化分开求解，位置误差修正直接改变位置/旋转，不累计进速度。下载到的该头文件与 Jolt v5.5.0 相同，SHA256 为 `f9e29dce20ab39c83299302c9bfb95406d7c517e4dffa7895a75e859dfa2afed`。

进一步采集四个种子、每 5 ms 的位姿与求解器速度，全部 100 个决策帧仍与原始轨迹完全一致。`p[t+1] - p[t] - dt*v[t+1]` 的根部预接触最大残差仅 `1.16e-7 m`；落地左脚最大残差达 `1.466 mm/步`，右脚 `1.190 mm/步`。这支持存在不反映在求解器速度中的位置调整，但包含接触与连接稳定化，**没有测得每条约束的独立冲量**。

临时 GPU 原型只做质量矩阵加权的同时投影，不是完整 Jolt 迭代器，也没有复制关节、摩擦和接触的交错求解顺序。因此它未通过不能用来否定整个 GPU 路线；结论是停止追加此类简化弹簧/投影拟合。若未来继续提高训练域保真度，应先比较耦合求解过程和接触切换的实测响应，不能仅匹配静态脚的位置。

## 有效的修复在输入层

原有 PlayBrain 已有角速度加减速限制，反向约需 80 ms，**不是瞬间从 +0.8 跳到 -0.8**。此前在 MotionControl 层加反向过渡的首个诊断，由于上游命令经过零，检测器清掉了状态，实际没有干预；该批结果不能解释为“0.2 秒过渡无效”。失败尝试和源码保留在 `yaw_probe_attempt_01/`。

有效版本放在产生原始目标的 PlayBrain/TwistRamp 层。仅在行走加速、存在相反方向转向目标时，以 `2 * sprint_vmax_ang / sprint_yaw_reversal_s` 限制反向速率，并将反向状态保持到经过零之后。固定试验值为 0.2 秒，没有扫描多个时长。转向起步、松键停止、普通行走和前进速度继续采用原有处理；默认配置为 0，旧契约保持。

16 个原始连续转向用例全部通过、零跌倒。失败种子第二段有符号转向速度从 `0.376726` 升至 `0.687692 rad/s`，超过原有 `0.48 rad/s` 门槛。干预前 6 秒的观测、动作、命令和控制目标完全一致，禁用过渡的完整 18 秒也与原始失败完全一致；实际干预窗口命令发生变化。全部 Python/原生影子检查通过。正式接入版本再与成功原型完整 900 帧对照，逐帧一致。

生产配置为 `control_config.walk.twist_limits.sprint_yaw_reversal_s`。这是一项 **控制契约修复＋已训练策略的组合收益**，不能记成新模型训练收益。未来学习课程也通过同一 Python PlayBrain 生成目标，避免训练和游戏使用不同的输入转向语义。

## 保留的失败与限制

- 分离位置投影的首次 canary 在根部四元数上出现 `1.10e-7` 差异。定位为约 1.85 个 float32 ULP；诊断容差改为 `2.5e-7` 后重试。动作/控制 `1e-5` 门、物理误差门和产品评分均未改变。
- 首次完整接入脚本按名字排除了历史 sprint 回归，清单断言在运行物理前终止。修正为固定开发种子范围外的七条原始回归；失败目录保留。
- 导出清单原先使用当前工作区文件列表索引旧快照；并行任务添加文件时会失配。现改为枚举实际导出快照，并有独立回归测试。
- 本轮不证明达到原版 MuJoCo 的最高速度，也不宣称轮滑旧缺陷已解决。普通九技能只要求不丢失既有成功；具体通过数在独立包回归中如实记录。
