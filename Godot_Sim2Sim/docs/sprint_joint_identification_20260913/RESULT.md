# 行走加速已通过平地验收并接入默认资源

左 Shift + W 加速，可同时 A/D 转向，松开 Shift 恢复普通行走。只对步行机器人启用。主游戏维修站启动与资源准备流程自动安装固定 S05 普通行走 + a402 加速组合；模型和校验随 Git 提交，不再依赖本机研究目录。原生 ORT 推理保持，游戏 Jolt 参数未改。

| 验证 | 结果 |
|---|---|
| 开发加速 / 普通 / 历史回归 | 128/128、128/128、7/7；零跌倒 |
| 保留种子加速 / 普通 / 历史回归 | 400/400、400/400、7/7；零跌倒 |
| 长直行实测 | 0.2324 vs 0.1931 m/s，加速 20.4% |
| 30 分钟模拟场内连续操作 | 通过，零跌倒、无自动复位 |
| 当前主游戏默认九技能配对回归 | 30/69 → 42/69；零旧成功丢失 |
| 独立试验包九技能回归 | 42/69 → 42/69；零旧成功丢失 |
| 独立包宿主 OS 键盘 | 左/右 Shift 区别、A/D、暂停、3 次复位、2 次切换均通过 |
| 主游戏实际平地区域 | 加速、左右反向、松 Shift、停止、复位和三机器人切换通过 |
| 代码回归 | 310 项：308 通过、2 项可选跳过 |

默认界面显示左 Shift + W、同时 A/D 转向和松 Shift 恢复普通行走；状态标签显示“加速行走”。[主游戏画面](main-game-sprint.jpg)。独立包还通过禁网 Ubuntu 24.04 ARM64 容器检查、30/144 FPS 生命周期对照；实际导出模型数值自检最大误差 1.42e-14，原型/生产及实际导出回放逐帧一致。

主游戏首次两条长路线分别碰到充电柜和台阶，发生跌倒，原始记录与画面保留；随后在有明确空间余量的维修位平地完成输入接入检查。**平地加速合格，不表示能避障、爬台阶或撞柜不倒。** 这两条碰撞失败没有算成成功，也没有删除场景碰撞。普通九技能的 69 项包含旧轮滑失败，因此“无回退”不是九技能所有任务均合格。

本轮没有训练新权重。有效变化是固定 0.2 秒的输入层反向过渡：旧失败种子转向响应从 0.3767 提至 0.6877 rad/s。原来已有约 80 ms 的角速度斜坡；第一版附加在错误层的原型没有实际干预，失败已存档。连接平移、分离位置投影等 GPU 代理均未通过完整门，未采用。完整依据见 [研究分析](RESEARCH.md)。

独立包：`dist/MicroDuck-ARM64-20260913-sprint-reversal-trial/`；18 秒连续转向录像位于会话 `demo/demo.mp4`。该包保留上一批已核验的其他八技能；主游戏默认接入仅替换 walking 并增加 sprint，现有轮滑/Sai 版本不被替换，两套清单分别记录。主游戏已有 Sai Python 控制器仍保持原状；MD 的策略推理在 Godot 内完成。

性能测量只在本轮其他任务结束后执行，其他用户程序保留。1800 秒模拟耗时约 152 秒，约 11.9 倍实时，RSS 峰值约 187 MiB；具体延迟分位数、内存序列、CPU 亲和性和宿主负载见机器证据。

源码发行检查还发现全局 `*.onnx` 忽略规则会使 wheel 漏掉已跟踪的两个模型，现已为已验收模型添加精确例外；重新构建 wheel 后七个资源全部存在、字节校验一致，首轮失败保留。

合并主线时保留维修站的 scene_override 和新训练的状态/动作契约。隔离 worktree 的资产符号链接使首轮四项测试选错场景，失败保留；使用原始资产根目录重跑合并源码，306 项核心检查通过（2 可选跳过）。没有通过跳过失败测试来提交。
