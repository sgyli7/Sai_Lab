# MicroDuck 前向动态步态：研究与首个受控实验

检索及结果更新日期：2026-09-14。研究基线为本仓库 `b51298157fc6e06cc427f945ff4a7ba5f98ab9b2`。本文件记录一手资料、代码审计、预登记建议和主任务已完成的实验结果；没有在研究子任务中训练、改游戏物理或替换模型。第 1–5 节保留实验前的研究与分流规则，当前结论见第 6–7 节。

**当前结论：E1 有效摆动目标在本次实现、预算和两种训练 seed 下失败，四个续训候选全部拒绝。纯 tracking 续训没有原生净速度收益，support 两组还新增 12 / 10 次跌倒；默认 0.30 仍通过 32/32。跨后端命令、技能选择与有效控制配置已核对，但尚未定位唯一物理差异。下一项应研究有界的原生 replay 适应；SAC 新训练栈尚未实现，不能承诺有效。**

**审计纠错：** 调研初期曾依据通用代码的分桶字符串，误判 a402 对全部高速阶段施加了慢走教师。本次沿配置 SHA 追到真正 NPZ 后确认教师数据只有普通 / 静止命令，见第 3 节。这个假设已撤销，未将基于错误数据的冒烟测试计为有效对照实验。

## 1. 这次不再重复什么

已经核查的本地证据来自[输入与步态诊断](sprint_input_diagnosis_20260914/RESULT.md)及[MicroDuck 竞速研究与后续迁移记录](research_microduck_racing_20260912.md)：

- 桌面 W / Shift+W / S 实测约 `+0.188 / +0.234 / -0.287 m/s`。Shift 确实选中 sprint；同幅命令下反向跟踪也较快。前向 sprint 相比普通走主要增加了一点步长，尚未证明形成新的动态步态。
- 同模型只提高 sprint 命令 `0.30→0.45`，32 条原生课程从 `32/32→10/32`；新增问题是方向、转向和退出质量。不能再把这一操作当作优化方案。
- 社区高速 MicroDuck donor 的原生推理契约已核对，但直接迁入冻结 Jolt 后全部跌倒；不同启动方式也不能解决。已发现高速工作区的执行器可达扭矩差与接触状态投影误差，不能从源 MuJoCo 的速度推断本游戏可用。
- 历史 / 接触观测消融、原生采样纠正和多组代理接触 / 关节参数尝试已经做过。不能仅因新论文使用历史、接触或随机化，就再无差别重复这些路线。

## 2. 一手成果中真正有用的部分

### A. 2026 年真实跑步：目标可控，比姿势看起来像更重要

[Chasing Autonomy，2026-03-26 预印本](https://arxiv.org/html/2603.25902v1)在真实 Unitree G1 上报告最高 `3.3 m/s`、数百米室外运行和避障。其比较结果支持经过动力学约束优化的周期参考，而不是直接使用运动学重定向；同时仍需独立的速度命令目标。actor 使用普通前馈网络和相位输入，参考轨迹只用于训练；训练包含开环速度、航向闭环、航向加侧向闭环，并专门覆盖走到跑的状态。它证明这条研究路线有真实机证据，不证明 MicroDuck 能达到相同速度。

作者[公开实现](https://github.com/Zolkin1/robot_rl/tree/3c280e185e801060e6a73e77fa4ab2b650372ebb)含 IsaacLab 训练、MuJoCo sim2sim 和硬件运行路径。[固定 running 配置](https://github.com/Zolkin1/robot_rl/blob/3c280e185e801060e6a73e77fa4ab2b650372ebb/source/robot_rl/robot_rl/tasks/manager_based/robot_rl/g1/g1_running_clf_env_cfg.py)分别实现参考类型、参考奖励和速度目标消融，还混合三类操控命令。**注意该提交文件顶部默认为 `TRACKING_REW_TYPE="ADJ"`、`TRAJECTORY_TYPE="DYNAMIC"`，不是论文最佳 `GOAL + DYNAMIC_HD`；不能把仓库默认入口误当最终配置。** 应固定具体实验配置及参考数据后复现。

**对本项目的推断：** 高速稳态、方向纠偏、A/D 和退出必须是同一个训练任务的组成部分。无需为参考库或轨迹优化在游戏中增加一个在线规划器；它们可以仅在离线训练阶段提供目标。CLF 形式的奖励也不等于这个离散学习控制器获得了数学稳定性保证。

### B. 工业落地的 Disney：把动作质量写成目标，再让策略满足物理

[Disney 的 RSS 2024 原论文](https://arxiv.org/html/2501.05204v1)区分持续、周期和定长动作，周期策略显式接收相位，使用任务空间运动参考与路径坐标，训练包含可交互的速度命令；足端和躯干参考先经过运动生成处理，最终仍由反馈策略维持动态平衡。其步行有真实机跟踪评测。公司[2025-04-03 第一方说明](https://thewaltdisneycompany.org/news/behind-the-bdx-droids/index.html)确认 BDX 已在 Disneyland 和 Disney Wish 与游客见面，这是实际娱乐部署证据，而不只是仿真演示。

[Olaf，2026-04-02 修订版](https://arxiv.org/html/2512.16705v2)进一步把角色步态、关节限制、落脚冲击和热约束纳入学习。作者比较了有无 heel–toe 参考和冲击代价；实机 5 分钟冲击实验报告平均声级降低 `13.5 dB`，同时大体保持参考运动。它针对的是角色步行，不是高速跑步证据。

**对本项目的推断：** “沿正确方向移动”和“身体前送、双腿交替承接、视觉上有节奏”应分别测量。我们不需要模仿 Disney 的硬件、PD 或身体比例，但应借鉴其任务表达：动作风格必须是显式目标，不能期待速度奖励自动产生某一种外观。当前仅靠一个“速度提升百分比”的通过门槛存在产品定义缺口。

### C. 同类低成本鸭形机器人：有参考库和板载 ONNX，不等于已有高速解

[Open Duck Mini V2 官方项目](https://github.com/apirrone/Open_Duck_Mini/blob/v2/README.md)提供真实机步行展示、参考生成器和板载运行仓库。其[固定训练源码](https://github.com/apirrone/Open_Duck_Playground/blob/b9be205ac64488c23504ca42e5ec790337adeec3/playground/open_duck_mini_v2/joystick.py)明确使用周期参考、sin/cos 相位、独立线 / 角速度跟踪和 ONNX 可导出的策略；默认前向命令范围仅 `[-0.15, 0.15] m/s`。因此这份源码适合作为小型鸭形机器人参考任务的实现样本，不能当成高速跑步配方。

其[参考表示实现](https://github.com/apirrone/Open_Duck_Playground/blob/b9be205ac64488c23504ca42e5ec790337adeec3/playground/common/poly_reference_motion.py)和[生成器](https://github.com/apirrone/Open_Duck_reference_motion_generator/tree/3d7bc6fd80e6c35587b2a5279314d946cf63456b)可以帮助实现离线周期数据。生成器存在不代表生成出的每条轨迹都符合我们的冻结电机和 Jolt 接触，仍要验证。

[EmoLo 作者项目，RO-MAN 2026](https://mertcookimg.github.io/emolo/)在 Open Duck Mini V2 上实现风格条件化的单策略、ONNX 板载运行，并给出真实机前走 / 头部姿态对照。其实机协议是 5 秒恒定前走；它支持“小型机器人能把可解释风格与移动共同学习”，不能支持长时间、高速或复杂转向可靠性。

### D. 周期奖励是低成本的步态结构描述，但必须正确提供相位

[Periodic Reward Composition，ICRA 2021](https://arxiv.org/html/2011.01387v2)用周期足端力 / 速度代价定义左右支撑与摆动，并在 Cassie 实机展示多步态和转换。摆动阶段抑制脚受力，支撑阶段抑制脚滑动；边界平滑而非硬切。论文明确要求策略看到周期信息，避免隐藏时钟造成任务状态不充分。其实现还学习 PD 增量，且控制频率不同，本项目不能照抄这些部分。

[SRBM 参考轨迹研究，2022](https://arxiv.org/abs/2207.04163)通过离线简化动力学轨迹辅助 RL，在 Cassie 上展示 `3.0 m/s` 的 grounded running。**因此不能仅凭没有腾空就断言不是动态跑步，也不能为了拿到腾空指标奖励原地跳。**

**对本项目的推断：** 在没有可靠 MicroDuck 高速参考库时，周期支撑 / 摆动任务比直接导入人类动捕更适合作为下一项结构实验。它给出节律约束，让足端和身体在冻结物理中学习具体动作；不过仅有周期奖励仍不保证步长、方向和起停质量。

### E. 最新论文不能只读标题

| 一手工作 | 可以采用的证据 | 不应推出的结论 |
|---|---|---|

## 3. 教师数据核查：撤销不成立的首实验

主任务沿 a402 配置找到真正使用的 `results/sprint_joint_gpu_20260912/teacher/manifest.json`，研究子任务又独立计算文件哈希并读取了 NPZ，得到：

| 项目 | 实际值 |
|---|---|
| manifest SHA256 | `e55754df448f6f2f0a57bd5317a748a1980b6792a3b10adf367f04221221ab47` |
| NPZ SHA256 | `aaf3bef6d7e05afed2a2bd261be1e8acf1d86745480922470f40bf5d0d5041ba` |
| 形状 | `11488 × 61` |
| 命令 vx 范围 | `0.0…0.25 m/s` |
| `vx≥0.275` 行数 | `0` |
| builder / manifest 的选择说明 | 只保留成功 S05 的普通速度 / idle 状态；候选当前恢复状态不受教师保护 |

[通用 retention 代码](https://github.com/sgyli7/Robot_Godot_Sim2Sim/blob/b51298157fc6e06cc427f945ff4a7ba5f98ab9b2/src/sim2sim/research/walking_retention.py)支持 idle / normal / sprint / turn 分桶，不代表每次提供的 replay 含有四个分桶。此前把通用 `audit.phases` 文案当作实际数据内容，是证据使用错误。**不再做“移除稳定高速教师”的消融，因为本模型的这部分数据本来就是空的。** 原计划中基于另一份数据运行的有限冒烟不构成该假设的实验结果。

教师损失仍为 `0.02 × 0.5 × mean(sum((delta / 0.02)^2))`，并非可仅凭权重认定很弱。但这一约束施加在实际的普通 / idle replay 上，不能把其数值量级写成“高速段被教师锁住”的证明。它是否通过网络泛化影响高速仍需新的独立假设与证据，当前不值得优先重训。

可确认的结构缺口是：[当前训练器](https://github.com/sgyli7/Robot_Godot_Sim2Sim/blob/b51298157fc6e06cc427f945ff4a7ba5f98ab9b2/scripts/sprint_gpu_train.py)主要使用命令跟踪、航向 / 路径、倾斜和动作变化代价，没有足端摆动、承接或落脚任务；[残差模型](https://github.com/sgyli7/Robot_Godot_Sim2Sim/blob/b51298157fc6e06cc427f945ff4a7ba5f98ab9b2/src/sim2sim/research/models.py)仍在 S05 周围限制为 `±0.2 rad`。缺少步态目标是源码事实，“残差边界是主要瓶颈”则尚未证实。

## 4. 首实验：由接触事件和前进质量门控的摆动目标

**假设 E1：** 当前速度跟踪能通过短步、保守支撑等多种方式满足，缺少显式有效摆动目标限制了向前推进的学习。保持同一个 61 维 actor 和控制契约，只加入与真实接触状态有关的步态任务，可能带来有效步长 / 前进速度的改善。

这个方案不引入 actor 看不到的外部周期时钟。奖励所需接触计时仅在训练器中累计；它仍有历史依赖，不能由此声称当前 actor 已具有完全可观测性。先利用现有策略已经能够表达步行周期的事实做结构筛查；如需外部指定相位，必须按第 5 节显式扩展输入。

### 一手实现依据与不能照抄的部分

Pollen 官方 [velocity 配置，固定提交 `1e79c29`](https://github.com/pollen-robotics/microduck_rl/blob/1e79c29c97d8b38aee9eefde77a545860ba7658e/src/mjlab_microduck/tasks/microduck_velocity_env_cfg.py)使用 `air_time` 权重 `3.0`、窗口 `0.125…0.300 s`，以及 `0.02 m` 的足端净空 / 摆动高度目标。其行走运行接口仍是 61 维，官方项目有真实 MicroDuck 策略部署。但该配置不是本游戏高速成功证据，BAM 与冻结 Jolt 的差异也没有消失。

已沿依赖读到 [mjlab v1.3.0 的真实奖励实现](https://github.com/mujocolab/mjlab/blob/v1.3.0/src/mjlab/tasks/velocity/mdp/rewards.py)：`feet_air_time` 在**当前离地时间落入窗口时逐步给分**，不是落地时一次性给分；其基础形式会把两脚得分相加。`feet_swing_height` 才是在首次接触时评价本次最高抬脚高度。两种任务不可混称，也不能把逐步奖励的权重原样复制到低频落地事件奖励。

标度也要核查：源配置线速度权重为 `2.0`，本地线速度项最大为 `1.0`，直接加入 `3.0` 会改变相对重要性。若只保留来源比例，单脚有效摆动的候选权重可取 `1.5`，这仍是待验证的新设计，不是已验证最优值。[源 reward manager](https://github.com/mujocolab/mjlab/blob/v1.3.0/src/mjlab/managers/reward_manager.py)默认还统一乘 `step_dt`；复制个别原始数字不能代替完整奖励标度审计。

**本项目适配建议，属于新实验设计而非源论文结论：** 保留窗口作为一个预登记起点，但把步态得分限于 sprint、正常站稳判据内、有实际目标方向进度的有效单脚摆动。对侧应有有效支撑，摆动脚应有真实净空；不能因两脚同时抬起获得双倍奖励。普通走、idle、退出后不激励抬脚。前进门控使用真实位移 / 速度投影，不能只看用户发出 W。

最小形式可表达为：

```text
r_gait = weight × selected_sprint × upright × progress_gate
         × valid_single_foot_swing_in_airtime_window
```

其中净空必须来自鞋底 / 实际碰撞几何相对地面高度；踝关节中心高度不能直接当净空。`progress_gate`、接触滤波、窗口边界、权重归一化均应训练前固定并记录。若用正向短窗速度作门控，需要同时保留独立航向 / 横向评分；身体朝偏方向跑快并不代表沿目标方向推进。

初次不要同时增加多个幅度奖励或固定前倾角。新目标是一项“有效摆动”的复合任务：仅奖励原地跳、拖脚平移、跌倒摆腿均不能获得相同收益。左右交替、足底滑移、腾空和落脚冲击先作为监测项；若模型利用单腿连续跳等漏洞，保留失败并针对这个漏洞修改下一项实验，而不默默挑掉轨迹。

### 配对配置

主任务已选择两组相同的 a402 暖启动、`0.45 m/s` sprint 命令和完整键盘课程。建议固定如下：

| 项目 | A：对照 | B：候选 |
|---|---|---|
| 普通 walking / idle | 冻结 S05 | 相同 |
| 初始 sprint、网络 / std / bound | a402，61 维有界残差 | 相同 |
| 教师 replay | 上述准确 SHA 的普通 / idle 数据 | 相同 |
| PPO / CaT / 原有奖励 / 全部键盘课程 | 当前固定配置 | 相同 |
| GPU 代理、电机、接触、游戏物理 | 同一冻结版本 | 相同 |
| 新增有效摆动目标 | 关闭 | 开启 |
| transition 预算、训练和开发评测种子 | 事先登记 | 相同 |

新增目标前先做有限冒烟与反例检查：静止、倒地、双脚离地、仅拖脚、有命令无进度，不应得到有效步态分。正常交替前进应得到分数；接触 / 计时应在复位和切换时清理。反例检查不是正式性能提升证据。

### 固定测量与判定

1. **训练有效性：** 两组实际 CUDA 采样 / 学习、相同 transition 预算；记录分阶段 reward、成功 / 终止原因、KL、有效更新数、残差 RMS / P95 / 接近边界占比及步态得分触发率。单对训练只能作筛查，不能宣称统计显著。
2. **代理内行为：** 相同起点下的直行、持续转弯、反向转向和退出。测目标方向位移速度、横向误差、航向、停步、单 / 双支撑占比、足端滑动、步长、摆动时间和左右交替。不能把估算速度变化说成地面推进冲量。
3. **原生 Jolt：** 两组与未续训 a402 在相同高命令下配对，另保留默认 `0.30` 回归基线，区分模型进步和命令改变。正式测量暂停竞争任务；Godot 有限并发、timeout 和受管进程。
4. **产品门槛：** 原生目标方向速度争取 `≥0.35 m/s`，完整转向 / 退出无新增失败、无跌倒；普通行走速度至少保留 95%，停止 / 复位不回退。达速度仍只是速度阶段进步；动态步态还要看身体与足端周期、同视角原速视频及连续操作。
5. **去留：** 如果 B 只在 GPU reward 或短直线变好，不替换默认模型。开发通过后冻结候选，用未参与调参的最终种子验收，不根据最终结果继续挑参数。

## 5. 实验结束后的分流规则

### 情况一：接触目标有效，但节律不一致或变成单腿跳

保留现象，下一项比较**显式周期支撑 / 摆动目标的开 / 关**。为隔离目标贡献，两组都提供相同 sin/cos 相位、相同容量和课程，仅周期目标不同；不要同时改动作范围、姿态代价与速度奖励。

这需要新观察契约，例如 `61+2=63` 维，而非挪用现有 head / body command 字段。相位在物理决策步推进，明确切入、退出、暂停、复位语义，同步 Python / 原生实现和数值对照。只在 reward 中塞入 actor 看不到的外部时钟不是完整实施。

周期目标优先描述左右交替支撑、摆动期卸载、支撑期少滑移和足端净空。周期 / 支撑比从当前实际步态量级起步，保留命令和过渡目标；不先强制腾空。有效后再单独研究频率与速度相关周期。

### 情况二：原生步态改善受限，残差明显触顶

核对哪些关节、哪些阶段触顶，以及动作是否仍在有效执行器区间；tanh 边界占用不代表需要更大电机力。随后单独比较全量 actor：把 a402 在完整状态分布上蒸馏为无慢走 anchor 的同规格策略，确认初始原生输出 / 行为可比，再放开训练。保持已固定奖励和课程，不同时加入相位或扩大指令。

这回答“策略表示是否受小残差局部邻域限制”。外部高速 MLP 成功说明简单前馈网络可以表达高速步态，不是 full actor 必优于 residual 的因果证据。

### 情况三：步态目标无收益，残差也没有显著触顶

不要推导成“网络太小”。先检查有效步态分触发率、奖励是否被门控恒置零、接触读出是否可靠，以及 KL / 风险终止是否让学习几乎没有发生。若实现和学习正常但仍没形成承接，优先显式相位或可行参考；不要围绕同一时间窗无限扫描参数。

### 情况四：GPU 明显改善，原生 Jolt 恶化

暂停扩大速度。只采新候选失败前落脚 / 推进 / 转向短段，与已成功旧步态作配对：分离初态投影误差、同动作单步误差、数十毫秒接触响应和闭环累积偏差。按整条轨迹划分开发 / 保留段，避免邻近帧泄漏。

只有可定位的误差结构才值得修改 GPU 代理，游戏 Jolt 和冻结参数保持不动。先证明修正在独立短段改善且不伤害站立 / 普通走，再重训。已失败的接触参数搜索不会因为换了论文名就成为新方法。

### 情况五：有节律仍不会有效前送

建设 **MicroDuck 自身的动力学可行参考库**：由本机器人关节范围、执行器速度—扭矩可达区、足端无滑接触和周期闭合条件出发，联合约束重心推进与落脚位置，使用 GPU 代理优化候选周期，再由冻结 Jolt 校验。左右足端 / 重心目标比完整人类姿势更适合其形态；鸭形参考生成器可提供表示与初值，不能保证可行性。

参考库至少区分稳态、走到跑、跑到走 / 停，速度目标仍独立存在。参考用于训练指导，不用设置刚体轨迹、瞬移、关闭接触或更换游戏后端直接播放。若找不到可行参考，如实报告当前约束下尚未找到。

## 6. 研究落实边界

当前优先级是 **E1 已完成并拒绝全部候选 → 有界的原生 replay 适应研究与接入验证 → 固定预算的原生对照**。E1 的失败否定本次配方，没有证明一切步态目标都无效；原生命令 / 技能 / 配置对照已完成，不再把它写成待办。继续按失败短段诊断可定位的观测、控制和动力学差异，不直接跳到相位、扩 bound 或批量扫参数。基于错误教师数据判断的更早假设仍维持撤销。AMP、Transformer、LSTM、多目标 AMOR、在线 MPC 各解决不同问题，目前没有证据应同时引入。

研究访问作者论文、公司 / 作者项目页、固定 Git 源码和模型卡。数字区分源仿真、作者实机与本地原生测量；不把宣传标题、转引视频速度、不同机器人性能或未复现模型卡作为本项目已达成能力。没有从互联网取得可直接替换本项目、且已验证完整操控的高速 MicroDuck 策略。

源码层面，作者 `panda-rl-kit` 明确将机器人端采样与 CUDA 学习服务分开；这支持本项目采用分批采集 / GPU 学习的系统结构，但该仓库公开的是 Panda 接入栈，并不是可直接运行的 MicroDuck / Go1 适配器。[官方 README：Safe-Learning Trainer](https://github.com/yardenas/panda-rl-kit#safe-learning-trainer)

应同时报告 `u = 梯度更新次数 / 新 transition 数`、`rho = 更新次数 × batch_size / 新 transition 数`、独立物理 transition 数、采样和学习各自耗时。把一次包含 N 个环境的 vector step 当作一条 transition，会把所谓 UTD 放大 N 倍；PPO 在一次 rollout 内本来也有多 epoch，准确区别是能否跨策略版本复用历史经验，不是“PPO 每条数据仅看一次”。

### 下一策略：有界的原生 replay SAC 适应试验

**这是尚未实现的研究建议，不是论文已验证的 MicroDuck 配方；SAC 新训练栈和下述试验均未完成，也不承诺有效。** 优先级是复用真实 Jolt transition，先验证少量目标域数据能否产生有用的策略更新。无需把 Jolt 搬上 GPU，也无需现在复制一套 C++ Jolt 仿真器。拟以现有共享物理 / 控制的 headless 入口做受管批采集，GPU 做 Q 与 actor 更新；完成批次即关闭采集进程。

1. **冻结起点。** 用同一 a402、`0.45` 命令、现有 61D / 14D、有界残差、普通 S05、普通 / idle 教师和纯 tracking 奖励。不要同时加入相位、扩大 bound、降低姿态代价或改游戏物理。奖励在 native 端按相同定义计算并校核量纲；已失败的 support 目标不并入此对照。
2. **先补数据契约。** 每条保存 actor obs、privileged critic state、实际执行动作、动作后 next state、reward、terminated、truncated、技能 / 控制版本和 episode / policy ID；保留终止前状态。下一状态属于普通 walking 时，Q bootstrap 的 next action 应来自冻结 S05，不能无条件调用 sprint actor。控制器 / 观察器历史应可复现，不能把 61D actor obs 宣称为完整物理状态。旧教师 replay 不是 reward transition，不能冒充 SAC buffer。
3. **承认迁移成本。** a402 提供 PPO actor，没有可继承的 SAC Q、target Q、温度或优化器状态。先验证新 actor 均值与 a402 数值一致；冻结 actor，用原生旧策略数据训练 / 校核新 critic，然后才开放 actor 更新。不能仅加载 actor 就宣称完成论文中的 SAC 暖启动。普通 actor 和模型输出契约仍冻结，critic 可使用现有 privileged 信息。
4. **一个固定筛查预算。** 建议两种训练 seed，每种各比较原生 PPO 与原生 replay SAC；每 endpoint 最多 50000 条新的原生 transition，包含最初 5000 条冻结策略采集。SAC 首轮固定 `u≈1`、actor / critic 更新比 `1:20`、actor LR `1e-5`，不扫 UTD；这些只是有来源的起点。两组从相同权重和采集课程开始，PPO 按其 on-policy 规则使用数据，不能强行用固定离策略 tape 训练 PPO。另记录新 critic 初始化、学习时间和全部准备成本，避免只比较采样时间。
5. **保证批采集是同一目标环境。** 先限两个 headless worker，记录 transition/s、CPU、IPC、推理和更新耗时；只有 profile 证明并发有净收益才扩展。进程受统一超时与退出清理管理。正式评测停采样和训练。批采集与算法样本效率是两个变量：不要同一次实验既改采集物理实现又改 learner。

这个试验需要完整可执行的 SAC 接入和审计，不应挤成“今晚剩几分钟再跑一个”的临时补丁。

### 如何证伪，以及其他路线排位

训练前固定最终 endpoint 和开发种子。筛查的工程门槛可设为：两个 SAC seed 相对相同命令的 a402 都至少多通过 4/32，配对 long 净位移速度提高至少 5%，无新增普通行走 / 退出回退；并在相同新 transition 预算下优于 PPO。该门槛只决定是否继续投入，**不是上线标准或统计显著性结论**；上线仍需完整无跌倒、目标速度及最终保留种子要求。不要用 Q loss、预测 Q 或 reward 上涨替代原生评测。

若 Q 的保留轨迹预测误差恶化、预测增益上升而实际增益下降，停止放大更新次数，优先检查 critic 外推、状态 / bootstrap / 数据覆盖；小训练 loss 不能证明 Q 校准。若两个 seed 都没有原生净改善，否定本次预算与配方的实用性，不能归纳为“SAC 永远无效”。若有效但时间仍由 Jolt 主导，再独立评估多环境批采集工程。

| 备选方向 | 此时的安排 |
|---|---|
| 继续代理标定 | 保留必要诊断：固定动作和完整初态，在失败前短段测状态、接触时序和执行器误差，按完整 episode 划分保留集。只有可重现的误差结构才校正代理；已失败的参数搜索不重复包装。它仍可能是最便宜的修复，但不是见到 GPU/native 差距就能直接下结论。 |
| 原生多环境批采集 | 与 replay 互补，降低每条真实 transition 的成本；先测现有管线，避免另建一套不等价物理。若瓶颈确是物理积分，去掉 Python / TCP 不会自动获得 GPU 物理吞吐。 |
| 学习模型的短 rollout | MBPO 原文支持从真实 replay 状态分支、短至一步的合成 rollout，减少长期累积误差；证据主要是仿真基准。先在原生保留轨迹证明接触段预测和不确定性可用，再考虑给 replay 添加一步模型数据。目前代理本身已有域差异，不宜立即再加一个未经校核的模型。[MBPO §4–6](https://arxiv.org/html/1906.08253v1) |
| 完整世界模型 | DayDreamer 有真实四足在约一小时内学会翻身、站起、行走的证据；所以不能说世界模型不能处理腿式接触。但它是新的模型学习、记忆及 imagined-policy 栈，投入与本轮有界适应完全不同，暂不作为下一首实验。[作者论文](https://arxiv.org/abs/2206.14176) |

最终方向判断：**首轮 E1 与输入对照均已完成，四个候选全部拒绝；下一项优先研究并实现有界的原生数据复用与保守 actor 更新，代理标定按误差证据推进。** 当前没有定位唯一物理差异，SAC 栈尚未实现或验证。FastSAC / FastTD3 提供算法与工程候选，没有哪篇论文保证把当前 PPO 改名或换损失即可修复 MicroDuck 前进步态。
