## 这轮验证了什么训练方向

主要实验记录在 [EXPERIMENTS.md](EXPERIMENTS.md)，前置文献和源码研究在 [训练研究](../research_20260912_sprint.md)。

- **真实状态交接课程产生了本轮最佳候选。** S05 从已适配的 S03 出发，混合真实普通行走/转向/退出前缀后继续 Jolt 训练，开发集 55/64、长直行约 0.220 m/s。它同时使用新来源、横向目标与前缀分布，不能把收益归因于其中单项。
- **只继续同类 PPO 没有解决退出。** S06 同步部署反馈后，524,288 Jolt 步仍只有 47/64；S07 从更匹配惯量的 GPU 来源适配，393,216 步只有 3/16，均拒绝。
- **训练必须执行真实的普通/加速控制组成。** 旧课程松 Shift 后仍用学习 actor，部署却切回冻结普通 actor。新增 `native_composition_v1`：普通/idle 由旧 actor 实际执行，全程奖励进入 GAE/critic，仅实际执行的 sprint 行参与 actor PPO。500 行原生对照阶段零差异，观测最大误差 1.78e-14。
- **结构修正有支持证据，但收益还不够。** S08 真实组成和 S09 learn_all 对照固定同一来源、初始 ONNX、seed 86、代码、393,216 步及其他设置。S08 **52/64**，S09 **46/64**；长直行分别 **0.184 / 0.168 m/s**，均 0 跌倒。S08 优于同预算对照，但仍不及 S05 的 0.220 m/s，不能替换最佳候选。这是单训练种子的对照，不能宣称普遍成立。
- **GPU 训练域匹配改善存活，不自动改善操作。** 四个正式 GPU 代理各 2,457,600 样本，采样与 PPO 均在 CUDA。惯量映射配对在固定 Jolt 网格为 0/18 与 10/18 跌倒；但更稳的来源原生完整操作仅 1/16。惯量后编译补丁不满足实体惯量三角不等式，只是离线研究代理，不是 GPU Jolt 或官方认可的实体模型。游戏物理未改。

Jolt 适配的 PPO 更新使用 CUDA，但 Jolt 游戏物理和 CPU ONNX 采样仍走 CPU。独立应用的小批量推理保留 ORT CPU。GPU 代理的不同运行耗时包含编译和并存工作，不能冒称整条开发链路已经按同样倍数加速。

下一轮值得优先验证的是**联合普通行走、加速和停止的速度条件策略**，保留旧普通成功轨迹作教师约束。依据是：本轮大多数缺口在普通阶段，首次 Shift 前的失败更不可能仅靠修改 sprint actor 修复；未经训练的动作混合、保留策略和切换时重捕朝向也没有改善完整成功率。先建立真实部署课程和不同速度目标，再以同预算“联合策略 vs 已修正组成策略”检验；不是继续盲调 P 或加倍相同 PPO。新一轮必须另设最终种子，不使用本轮 920000–920029 调参。此方向是建议，未在最终测试后追加训练。

## 原生运行与普通技能回归

实际包的十模型自检，每模型 128 随机观测、时间/朝向边界及 64 个同 SHA 真实观测，最大绝对动作误差 **1.42e-14**，低于 1e-5。未将旧 DOUBLE 模型转成 FP32；S05 的来源本来就是 FP32。试验包九模型的 SHA256 与冻结的 **2026-09-11 候选包**全部相同，完整清单见包内 `models.json`。

区分两份已有资源：工作区默认轮滑 SHA 为 `cf05651d…`，上一轮候选包轮滑为 `c2f42293…`；本轮试验包沿用后者。这个既有差异不是本轮轮滑训练或晋级。默认工程和其九模型文件修改时间均早于本会话、SHA 自检一致，未被覆盖；本轮“九模型不变”和普通回归的比较基准是上一轮候选包。

最终包在禁网、只读、无 Python、无仓库的 **Ubuntu 24.04 ARM64** 容器执行最终集及九技能回归。容器固定镜像摘要，四核亲和性为 16–19，验收证据中保留环境检查及每条命令。

普通控制回归采用 23 个原有用例 × nominal/919000/919001 = **69 回合/包**，与 2026-09-11 旧包逐项配对：一般任务成功计数 **29→34**，未丢失原有成功，双方均无运行错误。五项改善均来自行走控制，不能算九模型训练收益；原有其他技能与轮滑质量缺口仍在。轮滑制动门另列在机器记录中，不拿“程序完成”代替技能成功。

工程收尾数据见 [RESULT.json](RESULT.json)。最终包在 30/144 FPS 上限下各执行 600 行复位/六次机器人切换回放，观测、上一动作、动作、命令和控制目标跨帧率最大误差 **0**，两次 Python shadow 均通过。实际稳态日志达到 30/144 FPS；模型重载期间有帧率下降，不能把限帧参数当成全程固定帧率。暂停/恢复和模型重载处理函数检查使用相同冻结代码的 Godot 工程；不等同于 OS 键盘验收。

30 分钟模拟时间的连续回放完成 90,000 次决策，无程序错误、无复位，实际约 151.2 秒（11.91 倍模拟速度）。**机器人在 222.48 秒走出 40×40 米地板，此后持续下落；这项吞吐不是 30 分钟场内健康行走的证据。** 原始 240 秒失败重放另保存在 `closeout/`，没有据此修改参数。该长测 sprint 推理 p50/p95/p99 为 **35/57/65 μs**，旧 walking 为 **221/263/307 μs**。RSS 从约 196.9 到 199.8 MiB，尾半段仍有约 2.2 KiB/s 增长，不能宣称内存完全无增长。测量时本轮其他训练和评测已停止，但宿主还有其他项目负载，进程快照与 load average 保留，非独占机器基准。

全量测试 **266 项：264 通过，2 项可选跳过**。最后一次运行覆盖提交 `bdf69e1` 的训练代码；之后只做冻结、验证和文档。失败尝试未抹去，包括初次轨迹命名覆盖（全部 54 条恢复重跑）、CLI 参数错误、release 不支持 `--script` 的超时、锁屏输入失败及准备证据路径错误。
