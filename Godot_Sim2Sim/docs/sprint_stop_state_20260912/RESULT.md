# 停止状态诊断与关节观测对齐：未晋级

本轮修复了一处 GPU 训练代理的明确契约差异，并完成一组固定预算训练。真实 Jolt 仍为 **127/128 加速、128/128 普通、7/7 已知回归，零跌倒**：旧停止失败消失，但新增连续转向响应不足。**没有证明整体改善，不替换默认模型，不更新安装包，不使用最终保留种子。**

## 停止失败为什么不能只归因于两个引擎

上轮最佳模型的 `sprint_shift_first / 927008` 在 9 秒松键后不能停稳，本轮用同一冻结原生工程连续复现 **3/3**。

在 9 秒决策前捕获全部刚体位姿、求解器速度、关节有限差分/EMA 缓存、控制历史、上一动作和会话时间。冷进程恢复时，模型、物理参数、最初构造关节的过程不变，不重新烘焙当前位姿的关节锚点。

| 对照 | 9 秒后停止结果 | 恢复瞬间动作/观测 |
|---|---|---|
| Jolt 连续运行 | 失败 | 基准 |
| Jolt 冷进程恢复，重复两次 | 两次均约 0.92 秒进入停稳 | 与基准逐值一致 |
| Jolt 同进程状态回填 | 失败 | 与基准逐值一致 |
| Jolt 同进程立即冻结/解冻并回填 | 失败 | 与基准逐值一致 |
| 上轮将可见状态投到 GPU | 约 0.52 秒进入停稳 | 上轮观测误差 3.73e-9 |

仪器化的完整连续轨迹与原版在观测、动作、命令、控制目标和上一动作上逐值一致。这个对照说明：**只恢复可见运动状态不能保证恢复同一个闭环物理过程**。目前尚未区分具体接触缓存、约束状态或冷构造的其他差异，不能宣称找到了某个求解器 bug。Jolt 自身的完整状态保存也分别包含全局、刚体、接触和约束状态；只有刚体恢复不等同于完整恢复。[Jolt 状态定义](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/StateRecorder.h)、[完整保存/恢复实现](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/PhysicsSystem.cpp)

冻结、回填和冷恢复全部只在隔离诊断工程中使用，**不属于候选玩法或验收修复**。新候选的正式回放没有这些操作。

## 已确认的 GPU 代理差异

原生 `physics_server.gd` 在 200 Hz 下从关节位姿差分估计速度，再使用时间常数 5 毫秒的 EMA；**策略观测、PD 阻尼和关节摩擦都读取这个速度**。GPU 代理原来读取求解器 `qvel`。失败快照里，两种关节速度最大差约 **0.605 rad/s**。

新增可选 `--velocity-observer joint_fd`，只对齐上述关节路径，默认 `solver` 行为保留，游戏物理不变。真实原生轨迹覆盖 2,400 物理步、600 决策步的差分检查：

- 关节速度最大误差 **1.21e-13**。
- 按实际原生控制目标计算的电机力矩最大误差 **1.59e-14**。
- 使用对应观测的策略动作最大误差 **5.55e-16**。

机身角速度的完整对齐原型没有通过严格检查：导出的机身四元数与原生内部 Basis 的数值/表示路径仍有差异，角速度误差 6.95e-5，动作差 1.05e-5。失败结果原样保留，未降低门槛；正式训练模式仍保留原来的机身角速度路径。此处是传感状态投影的比较，不是原生 ONNX 推理失败。纯四元数差分方法的解析测试通过，不能替代真实原生差分验收。Godot 的 Basis 旋转提取还涉及正交化，后续需要从内部 Basis 输入继续比较。[Godot Basis 实现](https://raw.githubusercontent.com/godotengine/godot/master/core/math/basis.cpp)

## 固定预算模型对照

独立从 S05 开始，使用相同训练种子 **953101**、分离策略、CaT、命令跟踪目标、教师来源及权重 0.02、八条键盘课程、256×64×512 = **8,388,608 转移**。只改变 GPU 关节速度观测及阻尼路径。

物理采样和网络学习均为 CUDA：采样 124.79 秒、学习 34.07 秒，训练循环合计 159.47 秒，零训练跌倒。模型导出误差 **1.55e-6**；这些计时不包含准备、原生验证或本轮研究工时。

## 下一轮可直接使用的原生采样入口

冷恢复会改变结果，因此下一步校正数据必须完整经过真实接触历史。本轮验证了隔离的原生随机策略采样：C++ ORT 运行均值策略，GDScript 只对加速动作加标准差 0.02 的高斯探索，普通动作继续冻结 S05；从真实复位开始跑完整键盘课程，无 Python/TCP 逐步控制，无失败状态移植。

四核测试共 18 条轨迹：16 条探索课程（环境初态种子 954100–954101）及两条无噪声对照。取得 **14,400 决策步 / 57,600 物理步**，回放用时 **12.56 秒**，约 **1,147 决策步/秒**。计时包含进程启动和轨迹写入，不含前置工程复制及后续 GPU 审计；不是完整训练吞吐量。

GPU 重建动作均值与旧策略采样对数概率，8,000 条加速探索样本的噪声分布符合声明；无噪声动作误差最大 **5.96e-7**，上一动作历史误差 0。18 条轨迹都携带训练标签，生产评分器明确拒绝把它们作为验收证据。`samples.npz` 内 `actor_mask` 只选择有噪声的加速样本；无噪声对照不能当作同一随机行为策略的 PPO 样本。

**这些数据尚未做任何梯度更新。** 下一轮应接入小批量真实 Jolt 校正和 GPU 学习，保留大规模 GPU 预训练：使用记录的行为均值/对数概率，重建真实后状态奖励与约束，限制策略改变量并保留普通教师，然后回到未修改的原生入口验收。不能把数据入口跑通当成模型改善。
