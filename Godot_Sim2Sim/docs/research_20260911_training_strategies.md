# MicroDuck 下一轮训练架构：文献与适用条件

调研截至 2026-09-11。本笔记只讨论路线选择，不启动训练、不使用旧保留种子调参。论文结果、作者开源状态与本项目建议分别陈述；机器人实机演示不等于商业规模部署。当前实现与样本量以 [本地审计](research_20260911_training_audit.json) 为准。

**建议主线：先修正任务与观测定义，在冻结 Jolt 中建立可用状态充分的目标域策略；再用原版 MuJoCo 成功轨迹提供动作质量参考。** 优先改变训练问题本身，而非立即更换 PPO、扩大神经网络或同时重训九技能。以下建议是结合本地审计与文献的工程推断，尚未通过新实验验证。

## 1. 直接目标域训练、多仿真训练与仿真辨识

PPO 仍是新一代机器人控制系统的重要组成。BeyondMimic 的公开训练实现采用 Isaac Lab/RSL-RL；2026 HoloMotion 的新贡献也包含面向序列的 PPO。它们改善的是参考数据、状态表征、难例采样及训练规模，不能据此认定本项目应该先替换优化算法。[BeyondMimic 代码](https://github.com/HybridRobotics/whole_body_tracking)、[HoloMotion 技术报告](https://arxiv.org/html/2605.15336v1)

对“最终就运行在 Jolt”这一目标，**目标域直接训练是必须保留的比较组**：没有真实硬件采样风险，也不需要先学习一套近似 Jolt 的替代动力学。若目标仿真样本便宜，应直接优化它；若慢到无法达到学习所需样本量，才值得引入快速源仿真。须同时报告等目标域样本量、等总计算时间两种结果；源域样本不能混记为 Jolt 训练量。这是实验设计建议，并非论文证明所有任务直接训练都最好。

**多仿真并非把样本简单混起来。** CROSSER（RA-L，2025-12）用跨仿真逆动力学模型识别动作不一致的状态，再对这些转移降权或过滤，显示普通联合训练也会遇到冲突。作者页确认方法与跨仿真结果，但本次未核实可直接复现的官方代码和训练成本，故列为备选机制，不能作为现成框架承诺。[作者摘要](https://z0ngqing.github.io/publication/crosser/)

**ASAP 的 residual 与现项目不是同一个位置。** 它先采集目标域轨迹，在源仿真内部训练 delta-action 模型来近似目标动力学，再在此仿真中优化策略；并非一直让最终控制器加一个小修补。论文包含 IsaacGym→IsaacSim/Genesis 与 G1 实机实验；实机全身模型数据不足，实际用了约 100 条轨迹训练 4 自由度踝关节补偿。官方已公开 delta 模型训练与微调入口。适用前提是源仿真明显更快、误差能由动作等效补偿、轨迹足够覆盖目标接触状态。[ASAP 论文](https://arxiv.org/html/2502.01143v1)、[代码](https://github.com/LeCAR-Lab/ASAP)

2026-04 的 proprioceptive distribution matching 进一步用关节观测与动作的分布距离适配仿真，减少时间对齐和动捕要求；Go2 实验报告少于五分钟实机数据。论文涉及参数辨识、action-delta、残差执行器模型；本次未找到可确认的作者代码。MicroDuck 能读完整引擎状态，首先使用同步短轨迹比对更直接；只有跨引擎状态难对齐时，分布匹配才有额外价值。[论文](https://arxiv.org/html/2604.11090v1)

冻结部署物理不妨碍诊断源模型误差，但**不应默默扩大下一轮授权**：质量、摩擦、重力或执行器的随机化与辨识若改变训练物理，须单列研究假设，最终仍在原始冻结 Jolt 验收。先随机化命令时序、初态和技能入口，不能用“工业界都做 DR”代替范围依据。

## 2. 全状态 actor、历史 student 与状态估计

RMA 用特权环境信息训练基础策略，再由历史推断适配变量；HIM 用本体历史估计速度和隐式系统响应。它们针对真实机器人无法直接测量的状态，分别有 A1、Unitree 实机证据与公开实现。HIM 项目中的 Cassie 扩展仅为仿真，不能称已验证所有双足。[RMA](https://ashish-kmr.github.io/rma-legged-robots/)、[官方链接代码](https://github.com/antonilo/rl_locomotion)、[HIM 项目](https://junfeng-long.github.io/HIMLoco/)、[代码](https://github.com/InternRobotics/HIMLoco)

本地审计显示 actor 的 61 维输入没有 critic 可见的 COM 速度、接触和高度等信息。对本地独立应用，这些是运行时可用信息，**不应为了仿照实机盲控而主动隐藏**。首先比较当前 actor 与显式加入速度、接触、任务相关高度的 actor。只给 critic 状态并不能让同一观测下的 actor 分辨不同速度。若全状态明显有效，而未来确实要上实体机器人，再训练历史 student；若无效，先排除奖励冲突与控制权限限制，不能继续堆历史长度。扩展输入须建立新版本契约，同步导出、原生推理和回放验证，不改当前冻结包。

DAgger 的作用是在 student 自己访问的状态上查询 teacher，缓解纯离线模仿的分布偏移；前提是 teacher 对这些状态仍能给出好的动作。MuJoCo 原策略在 Jolt 的失败状态未必是合格 teacher。宜先获得目标域可靠 teacher，再做蒸馏；旧 teacher 约束应当是有依据的局部先验，而非不可越过的动作答案。[DAgger 原论文](https://www.ri.cmu.edu/pub_files/2011/4/Ross-AISTATS11-NoRegret.pdf)

## 3. 动作质量：参考跟踪优先于继续手搓奖励

DeepMimic 用示范轨迹定义动作，AMP 则从运动片段学习风格奖励，不要求显式选取每个片段；PHC 强調持续跟踪与恢复。它们为“既能完成，又像原版”提供了比奖励堆叠更直接的目标，但原始角色实验不等于小机器人已完成部署。[DeepMimic/AMP 代码](https://github.com/xbpeng/DeepMimic)、[AMP 项目](https://xbpeng.github.io/projects/AMP/index.html)、[PHC 代码](https://github.com/ZhengyiLuo/PHC)

BeyondMimic（2025）更适合借鉴其**跟踪配方**：自适应增加困难动作段采样。已复核 2025-11-13 v4：四个动作中三个在无自适应采样时至 30k 迭代仍失败，简单动作约 2k 对 4k。这支持集中困难段，不代表 MicroDuck 有相同倍数收益。开源主体是运动跟踪训练，并有独立部署仓库。v4 的 guided diffusion 在板载 Mini PC／RTX 4060 Mobile 运行，相关控制为 25 Hz；不要沿用早期 v2 的 offboard 描述，也不要把整套 diffusion 作为本项目 50 Hz ARM CPU 部署前置。[v4 论文及消融](https://arxiv.org/html/2508.08241v4)、[训练实现](https://github.com/HybridRobotics/whole_body_tracking)

MicroDuck 最便宜的参考来源可能是**同形态原版 MuJoCo 成功回放**，而非人体 AMASS 重定向。记录关节、根部运动、足/轮接触、命令与阶段；允许 Jolt 为保持平衡偏离精确逐帧动作，用根部方向、足端与接触时序作为可解释的质量约束。先测站起或踢腿这一完整技能，再测连续行走。若原版本身没有成功刹停参考，模仿无法凭空教会刹停，仍须目标域任务学习。

AMP 需要足够且合理的风格片段，判别器可能奖励“像示范”而不满足两秒制动；因此任务成功仍单独约束。2026 SIGGRAPH 的 SMP 让预训练 score-matching 动作先验成为可复用奖励，项目有 Sony/Snap/NVIDIA 合作作者，但展示的是仿真人形角色，尚非本机器人或量产控制证据；列长期观察，不作为本轮起步依赖。[SMP 项目](https://xbpeng.github.io/projects/SMP/index.html)

## 4. 九技能统一与分层：先统一契约，再决定统一网络

2026 MUJICA 与本项目的轮滑/多技能问题接近：共享策略接收 skill indicator，状态估计含速度、轮地距离和碰撞，低层学会后再训练高层选择器；作者报告 Go2-W 实机运行。其 4096 环境、单 RTX 4090、低层 30k 与高层 10k 迭代、200/50 Hz 配置可查，未报告可直接换算的本机小时数；项目页访问失败，本次未确认官方代码可下载。[论文](https://arxiv.org/html/2605.13058v1)

但 Go2-W 有四条腿和主动轮，MicroDuck 是双足被动轮，其轮扭矩动作及电机约束不可移植。可借鉴的是**状态可辨识、显式技能上下文、从真实前一技能终态训练下一技能**。当前九个按钮已经决定技能，无需先训练自动高层选择器；也不宜对冲突技能的关节动作直接平均。优先保留分技能头和明确过渡管理，若同预算实验说明共享表示无负迁移，再合并网络。

Residual RL 本身有接触装配实机依据，因此不能因本轮小残差收益有限就否定它。关键在于 base 是否足够好、修正空间能否覆盖目标控制、teacher 在目标域是否正确。比较有界残差与可自由优化的目标策略，才能分清限制来自安全锚定还是学习能力；不能仅比较不同 residual scale。[原始论文](https://arxiv.org/abs/1812.03201)

## 5. 最新工业成果的可借鉴范围与成本

| 路线 | 数据/成本一手依据 | 复现与证据边界 |
|---|---|---|
| 小型目标域 PPO / tracking | 不要求真实数据；参考可由同形态原策略生成 | 首先测本项目吞吐与学习曲线，论文 GPU 小时不能直接移植 |
| DeepMimic / MimicKit | 老实现注明单策略约 60M 样本、16 workers 约一天；新框架提供多后端和训练示例 | 源码公开；数字是作者旧平台经验，非本机预算估算。[说明](https://github.com/xbpeng/DeepMimic)、[MimicKit](https://github.com/xbpeng/MimicKit) |
| SONIC，2025→2026 | 最大实验 42M 参数、100M+ 帧、约 21k GPU 小时；公开 BONES-SEED 是约 288 小时的子集 | 2026-04 已发布训练代码、权重及 C++ 推理；有 G1 实机和工业软件集成，不能由此认定 MicroDuck 即插即用。[论文](https://arxiv.org/html/2511.07820v3)、[官方仓库](https://github.com/NVlabs/GR00T-WholeBodyControl) |
| HoloMotion，2026-05/07 | 官方 v1.3 报 0.4B 参数、2000+ 小时混合动作，v1.4 扩展重定向数据管线 | 公开训练部署代码与模型；参考条件 MoE Transformer 仍需机器人适配，Any Embodiment 尚在路线图。[官方更新](https://github.com/HorizonRobotics/HoloMotion) |

因此，有工业实践支持的方向是“**数据与物理契约 → 任务化课程 → 参考运动质量 → 目标域验证 → 必要时蒸馏部署**”。没有足够证据支持“换成一个最新大模型就解决九技能”。当前问题规模下，foundation controller 的数据制作和训练成本可能远大于收益。

## 6. 是否更换 PPO：值得对照，但不是第一刀

**FastTD3 / FastSAC 已有实机证据，不只是仿真排行榜。** FastTD3（2025-05）用并行采样、大 batch 和价值分布建模，在单 A100 上数小时解决多项 HumanoidBench；其实机展示为只控制 12 自由度的 Booster T1。论文同时发现，相同 reward 下 PPO 与 FastTD3 可学到质量不同的步态，回报分数不足以代表能否部署。[论文 §3 与图7](https://arxiv.org/html/2505.22642v2)、[官方实现](https://github.com/younggyoseo/FastTD3)

Amazon FAR（2025-12）的后续工作用 FastSAC/FastTD3 在单 RTX 4090、数千并行环境下，15 分钟训练出 G1/T1 全关节行走并展示实机部署；舞蹈等全身跟踪另用 4×L40s、16384 环境，不能混称都只需 15 分钟。论文指出慢仿真中重用历史数据、增加每批数据的优化次数有助于缩短时间，训练源码见 Holosoma。这是实验室实机与开源配方证据，非量产可靠性证明。[论文](https://arxiv.org/html/2512.01996v1)、[官方项目](https://younggyo.me/fastsac-humanoid/)、[Holosoma](https://github.com/amazon-far/holosoma)

本项目 Jolt 采样慢而网络小，**replay 重用有合理价值，适合在修正观测/任务之后与 PPO 做一项受控对照**。先用同一观测、动作域、奖励、课程，分别比较等新采样量与等实际时间下的成功/平顺度；允许两算法各自有预先限定的优化配置，不能把为 PPO 特调的一组参数当普适最优。记录 replay 年龄、更新/数据比、估值误差和未见初态表现，防止重复学习狭窄失败数据。旧数据只有在物理、动作语义及奖励可重算且一致时才可复用；SAC 并不能从缺失观测或错误目标中学出正确制动。

若未来获得便宜的 GPU 大规模采样，PPO 的简单稳健仍有工程价值；若仍受少量 CPU Jolt 环境限制，off-policy 的优先级上升。两种场景都应先实测吞吐再定预算，不用“15 分钟”承诺本机效果。

## 7. 开工前只批准可判别的路线实验

1. **观测瓶颈**：同一奖励、动作权限、预算，当前输入 vs 可部署全状态。若只有全状态收敛，先升级契约；两者均不学会则不追加历史网络。
2. **目标冲突**：离线检查每个命令的目标速度、朝向、阶段奖励与验收是否一致；不让转向指令同时被“回到初始朝向”奖励惩罚。未通过前不启动训练。
3. **适配路线**：同样状态与课程，旧模型有界残差 vs 初始化自旧模型但允许充分更新的目标策略。现有两个分支还同时改变容量、参数化和正则，不能直接归因于残差上限；权限归因需另做同结构消融。`state_input + anchor` 当前被代码拒绝，新状态兼容是前置。仅有 ONNX 时先验证可恢复权重或以行为克隆初始化，不假定检查点齐全。绘制新任务成功与旧任务损失，而非只看奖励。
4. **源域价值**：目标域单训 vs 源域预训后目标域学习；先统一状态/动作语义。只有样本或时间优势成立才继续双仿真或 ASAP 支线。
5. **参考价值**：一个技能的任务奖励 vs 加同形态成功参考。质量改善且速度/恢复不退化才扩展到其他技能；最后再做共享技能策略与 transition curriculum。

所有路线使用新的开发/验证划分；旧 916000–916029 保留集只能作历史结果。实验前写下可推翻假设的结果、训练样本预算、停止条件及全链路验收，不把九技能各六分钟当成算法能力结论。
