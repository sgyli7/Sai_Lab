# GPU 联合策略与命令目标试验：未晋级

本轮最佳候选在真实 Godot/Jolt 中通过 **127/128 加速、128/128 普通、7/7 已知回归**，全部零跌倒。仍有一次退出加速后的停止失败，丢失一个基准成功，未满足完整门槛。**不替换默认模型，不更新安装包，不使用最终保留种子。**

## CPU 与 GPU 实际分工

五个正式训练终点都使用 **CUDA 物理采样 + CUDA 学习**，每组 512 世界、256×64×512 = 8,388,608 次转移，合计 41,943,040 次。单组训练计时约 153–167 秒；例如最佳组采样 122.99 秒、学习 33.93 秒。配置、逐轮计时及终点记录在 `evidence/train_*/`。这里是训练循环计时，不含原生回放、准备与研究工时。

用户看到的四核负载来自无窗口的 Godot/Jolt 验证。游戏使用的 Jolt 仍在 CPU 上运行；这些回放必须保留，才能检验 GPU 训练成果在真实游戏中的行为。训练和验证均通过监督器限制在 CPU 16–19、nice 10，并设置超时及子进程清理。

目前没有证据表明 CUDA 算术有缺陷。真正剩余的问题是 GPU 训练环境与 Jolt 的动力学或状态表达差异；神经网络数值一致，不代表闭环运动一致。

## 固定对照与结果

每个原生完整组均为 263 条：开发种子 **927000–927015** 上八种加速课程及配对普通课程，共 256 条；另加六条此前失败和一条最小失败。全组无运行错误、无跌倒。比较器同时要求任务成功、没有丢失基准成功、每类普通速度至少保留 95%、配对加速至少 1.15 倍。不能只看训练奖励或 `completed.json` 中的局部 accepted 字段。

## 学到了什么

**共用 actor 本身不解决问题。** 冻结模型共用两槽能改善部分交接，却引入别处的轨迹失败；同预算共用策略继续追求速度，原生加速通过率降至 91/128。

**速度目标会与操控竞争。** 原有线性前进收益允许更快的运动抵消部分转向代价。新增目标采用有上界的线速度及角速度命令跟踪，匹配实际传给 actor 的横向修正与转向命令，并保留路径、平衡和平顺代价。公式取自 [CaT 论文 Table I 的 option A](https://arxiv.org/html/2403.18765v1)。这检验的是目标结构，不是遍历奖励权重；也没有照搬论文的全部训练配置。

这个差异在 GPU 域内也存在：与原生初态投影、相同输入带和动作后采样对齐后，共用速度组仅 **80/135** 加速及回归成功，共用跟踪组 **135/135**；双方普通组 128/128。因此失败不能全部归咎于 sim2sim。最佳分离跟踪组在 GPU 中同样 135/135，但原生仍有停止失败。

**普通右转训练覆盖确实缺失，但补齐并未直接解决质量问题。** 原八条课程经真实 PlayBrain 得到普通左转 101 帧、普通右转 0 帧；加速左右转均存在。新增八条移除 Shift 的配对课程后，实测所有 16 条都有采样，然而共享策略原生结果仍为 121/128、127/128、6/7。保留课程基础设施，拒绝这次模型。

教师保留使用 11,488 条成功的普通参考观测，来自此前冻结成功轨迹，过滤加速命令，权重固定 0.02。它约束参考状态上的遗忘，不能替代缺失的 on-policy 课程，也没有成功倒走参考。数据来源及哈希见 `evidence/teacher/manifest.json`。

## 停止失败定位与诊断修正

对最佳候选唯一失败的 600 行原生轨迹做 Python 控制/推理影子检查：技能选择一致，完整观测、命令、上一动作及控制目标误差均远低于 1e-5。正式五组导出误差最大 **1.55e-6**。

在失败用例停止前 9.0 秒，将 Jolt 根位姿、关节位置/速度、角速度、质心速度和上一动作投到 GPU，并恢复此前 450 步控制历史：初始观测最大误差 3.73e-9、历史命令误差 0。原生停止失败，投影后 GPU 在 **0.52 秒**进入停稳；GPU 自身状态冷启动对照为 **0.44 秒**。两者都使用冻结 S05 停止策略，没有训练。

该投影没有携带接触缓存，也没有完全保留 Jolt 关节柔顺造成的非理想连杆位姿。因此证据指向 **动力学或状态投影差异**，尚不能单独判定某个接触求解器是原因。见 `evidence/stop_state_probe/completed.json`。

另发现旧 GPU 诊断脚本按动作前状态评分，而原生评分按动作后状态。本轮保留旧证据，新增动作后且包含最后一帧的评分入口，八条真实轨迹差分最大 1.53e-13，缺失最终状态会报错。所有跨引擎数字以上述新结果为准。原生验收和训练奖励本来就用动作后状态，没有因这次修正改变。

## 拒绝的控制方案

把共用跟踪模型只放加速槽、普通还原 S05，仅 121/128。进一步试验加速转向闭环，虽提高至 124/128，普通及旧回归全过，但右转前进速度只有普通的 **0.873 倍**，不满足加速目的。该控制改动已从 Python、Torch 和 Godot 生产实现撤回；原型与测试保存在 `harness/feedback_code/`。

原型的四条控制差分检查通过，关闭功能的 23 条回放指标与旧实现逐值一致。这只能证明控制实现一致，不能证明模型质量合格。它是独立控制试验，未算成模型改善。

## 下一步方向与停止条件

1. 先做同一失败状态的 **Jolt 连续运行 / Jolt 冷恢复 / GPU 投影恢复** 三方对照，明确缓存、连杆位姿和速度投影造成多少差异。冻结游戏物理，校准离线训练域。
2. 用失败前后的短时接触、滑移、关节偏差和停止轨迹约束训练域参数；用未参与拟合的开发轨迹检查校准效果。只有差异减少才继续扩大 GPU 训练。
3. 保留命令跟踪目标和普通课程覆盖。若失败分布确认是交接状态覆盖，再比较失败状态课程/参考保留与统一策略，固定预算；不要只增加轮数或用减速、复位、改路径起点掩盖失败。
4. 开发门全部通过后才能冻结候选，使用仍未触碰的 **928000–928049** 一次性最终验收。旧 924000–924049、926000–926049 也仍未用；已用开发种子不升级为保留集。

## 收尾与交付边界

284 项测试中 **282 通过、2 项可选跳过**。默认九模型及物理相关共 15 个文件校验不变。11 份与 canonical runtime 字节相同的 prepared 临时目录已清理；模型、checkpoint、原始轨迹和必要运行资源保留，见 `evidence/local_artifacts.json`。

实际工时、监督任务终态和进程审计写入 `RESULT.json` 与 `evidence/closeout/`。本轮只交付训练/诊断基础设施和可复现实验记录，没有新的合格模型或安装包。此前试验包保持不变；OS 真实键盘验收仍未核定，九技能整体质量与轮滑制动的未通过项也未在本轮解决。**没有证明达到原版 MuJoCo 水准，完整用户目标仍未完成。**

本轮账本截至报告封存累计 **108.707 分钟**（上限 120 分钟），actors 为空，无未核定中断。最终校验索引和 Git 记账的少量时间未计入该截止值。22 个监督尝试均有终态；其中一次仅归档路径推断失败，修正为记录中的真实轨迹路径后有界重试成功，没有重跑训练或验收。资源审计时没有 Godot、训练进程或运行容器。
